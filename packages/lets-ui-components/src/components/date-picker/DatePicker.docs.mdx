O Date Picker seleciona uma data num calendário. Com `range`, seleciona um

## Range

Use `range` para escolher um período, como uma hospedagem, férias ou o filtro
de um relatório. O calendário mostra dois meses lado a lado, então um intervalo
que passa de um mês para o outro aparece inteiro. O primeiro clique marca uma
ponta e o segundo marca a outra, em qualquer ordem. Entre os dois cliques, o
intervalo acompanha o ponteiro ou o foco do teclado. `Esc` cancela a seleção
incompleta e mantém o valor anterior.

Se a segunda data vem antes da primeira, ela vira o início e a primeira vira o
fim. Ao fechar, o foco volta ao campo, que é anunciado com o período já em
ordem. As duas pontas fazem parte do período: em `2026-01-16/2026-01-21`, o
dia 21 está incluído.

Em telas menores que o breakpoint `sm`, os dois meses ficam um embaixo do
outro.

O campo mostra as duas pontas com `Intl.DateTimeFormat.formatRange`, que não
repete o que elas têm em comum: `Jan 16 – 21, 2026`.

</Lang>

<Lang lang="en-US">
## Range

Use `range` to choose a period, such as a stay, a vacation or a report filter.
The calendar shows two months side by side, so a range that crosses from one
month to the next appears in full. The first click marks one end and the second
marks the other, in any order. Between the two clicks, the range follows the
pointer or the keyboard focus. `Esc` cancels the incomplete selection and keeps
the previous value.

If the second date comes before the first, it becomes the start and the first
becomes the end. On close, focus returns to the field, which is announced with
the period already in order. Both ends are part of the period: in
`2026-01-16/2026-01-21`, day 21 is included.

On screens smaller than the `sm` breakpoint, the two months stack one below the
other.

The field shows both ends with `Intl.DateTimeFormat.formatRange`, which does
not repeat what they have in common: `Jan 16 – 21, 2026`.

</Lang>

## Digitação

Com `editable`, o campo vira uma caixa de texto e o calendário abre pelo botão
ao lado. A pessoa digita só os números. A máscara põe as barras, os pontos ou
os hífens na ordem do `locale`. O formato esperado aparece no placeholder e,
sem `hint`, também abaixo do campo, para continuar visível depois que a pessoa
começa a digitar. Barras e hífens ganham um espaço de cada lado, para separar os
campos:

| `locale` | Máscara          |
| -------- | ---------------- |
| `pt-BR`  | `dd / mm / yyyy` |
| `en-US`  | `mm / dd / yyyy` |
| `de-DE`  | `dd.mm.yyyy`     |
| `ja-JP`  | `yyyy / mm / dd` |

Com `range`, o campo recebe as duas datas: `dd / mm / yyyy – dd / mm / yyyy`.
O sinal entre elas também vem do `locale`, o mesmo que o texto do campo usa:
`–` na maioria dos idiomas, `～` em `ja-JP`.

O `value` só muda quando o texto forma uma data completa e válida, e cada
mudança emite `change`. Enquanto o texto está incompleto ou forma uma data que
não existe, como 30/02, o `value` fica vazio e o campo reporta `badInput`, com
a mensagem de `bad-input-text`. Com `range`, duas datas válidas em que a final
vem antes da inicial também reportam `badInput`, mas com a mensagem de
`range-order-text`. Em todos os casos, o texto digitado fica no campo para ser
corrigido. Colar uma data em ISO 8601, como `2026-01-16`, também funciona.

As letras do formato seguem o idioma do elemento: com a tradução `ptBR`
registrada, uma página em português mostra `dd / mm / aaaa`. Para outro texto,
use `format-text`, que vale para o placeholder, para o texto abaixo do campo e
para a descrição acessível. Com `hint`, inclua o formato no texto do hint, já
que ele toma o lugar do formato abaixo do campo.

</Lang>

## Typing

With `editable`, the field becomes a text box and the calendar opens from the
button next to it. The person types only the numbers. The mask adds the slashes,
dots or hyphens in the order of the `locale`. The expected format appears in the
placeholder and, without `hint`, also below the field, to stay visible after the
person starts typing. Slashes and hyphens get a space on each side, to separate
the fields:

| `locale` | Mask             |
| -------- | ---------------- |
| `pt-BR`  | `dd / mm / yyyy` |
| `en-US`  | `mm / dd / yyyy` |
| `de-DE`  | `dd.mm.yyyy`     |
| `ja-JP`  | `yyyy / mm / dd` |

With `range`, the field receives both dates: `dd / mm / yyyy – dd / mm / yyyy`.
The mark between them also comes from the `locale`, the same one the field
text uses: `–` in most languages, `～` in `ja-JP`.

`value` only changes when the text forms a complete and valid date, and each
change emits `change`. While the text is incomplete or forms a date that does
not exist, such as 30/02, `value` stays empty and the field reports `badInput`,
with the message from `bad-input-text`. With `range`, two valid dates where the
end comes before the start also report `badInput`, but with the message from
`range-order-text`. In every case, the typed text stays in the field to be
corrected. Pasting a date in ISO 8601, such as `2026-01-16`, also works.

The letters of the format follow the element's language: with the `ptBR`
translation registered, a page in Portuguese shows `dd / mm / aaaa`. For any
other text, use `format-text`, which applies to the placeholder, to the text
below the field and to the accessible description. With `hint`, include the
format in the hint text, since it takes the place of the format below the field.

</Lang>

### Range em dois campos

Com `editable range`, `range-fields="two"` separa as duas pontas em duas caixas
de texto dentro do mesmo campo. Visualmente continua um campo só, com um traço
entre as datas e o botão do calendário no fim. Na estrutura, são dois campos: o
rótulo nomeia o grupo, e cada caixa tem o seu nome, `start-label` e
`end-label`, para que o leitor de tela diga qual data está sendo digitada.

Cada caixa usa a máscara de uma data só, como `dd / mm / yyyy`. A ordem do
`Tab` é início, fim e botão do calendário. O foco não pula sozinho para o fim
ao completar o início. `Alt` + `↓` abre o calendário a partir de qualquer uma
das caixas, e escolher o período no calendário preenche as duas.

O `value` continua o mesmo do range em um campo, `YYYY-MM-DD/YYYY-MM-DD`, e só
muda quando as duas datas estão completas e em ordem. Com erro, só a caixa com
problema fica marcada com `aria-invalid` e descrita pela mensagem: a final,
quando vem antes da inicial ou passa de `max`; a inicial, quando vem antes de
`min`; a que tem uma data incompleta ou que não existe (`badInput`). Uma caixa
vazia não é `badInput`: com `required`, a que falta reporta `valueMissing`; sem
`required`, o campo continua válido e o `value` fica vazio até as duas datas.
Colar um intervalo em ISO 8601 em qualquer uma das caixas preenche as duas.

Sem `editable`, o range continua um botão só, e `range-fields` não tem efeito.
Cada caixa tem a largura da data, então as duas ficam tão próximas quanto no
range em um campo.

</Lang>

### Range in two fields

With `editable range`, `range-fields="two"` splits the two ends into two text
boxes inside the same field. Visually it remains a single field, with a dash
between the dates and the calendar button at the end. Structurally, there are
two fields: the label names the group, and each box has its own name,
`start-label` and `end-label`, so that the screen reader says which date is
being typed.

Each box uses the mask of a single date, such as `dd / mm / yyyy`. The `Tab`
order is start, end and calendar button. Focus does not jump to the end on its
own when the start is completed. `Alt` + `↓` opens the calendar from any of the
boxes, and choosing the period in the calendar fills both.

`value` remains the same as the range in one field,
`YYYY-MM-DD/YYYY-MM-DD`, and only changes when both dates are complete and in
order. On error, only the box with the problem is marked with `aria-invalid`
and described by the message: the end, when it comes before the start or goes
past `max`; the start, when it comes before `min`; the one with an incomplete
or nonexistent date (`badInput`). An empty box is not `badInput`: with
`required`, the missing one reports `valueMissing`; without `required`, the
field stays valid and `value` stays empty until both dates. Pasting a range in
ISO 8601 in any of the boxes fills both.

Without `editable`, range remains a single button, and `range-fields` has no
effect. Each box is the width of the date, so the two sit as close as in the
range in one field.

</Lang>

## Mês e ano

O mês e o ano no título do calendário são botões. Um clique no mês troca os
dias por uma grade com os doze meses do ano; um clique no ano, por uma grade de
doze anos. As setas do cabeçalho passam um ano na grade de meses e doze anos na
de anos. Escolher um mês ou um ano volta aos dias no mesmo dia do mês, ajustado
ao tamanho do mês e a `min` e `max`. É o caminho do ponteiro para uma data
distante, sem clicar mês a mês.

Meses e anos sem nenhum dia dentro de `min` e `max` ficam desabilitados. `Esc`
ou um novo clique no botão aberto volta aos dias sem mudar nada. Com `range`, a
primeira ponta já escolhida continua marcada depois da troca de mês ou ano.

</Lang>

<Lang lang="en-US">
## Month and year

The month and year in the calendar title are buttons. A click on the month
swaps the days for a grid with the twelve months of the year; a click on the
year, for a grid of twelve years. The header arrows move one year in the months
grid and twelve years in the years grid. Choosing a month or a year returns to
the days on the same day of the month, adjusted to the month length and to
`min` and `max`. It is the pointer path to a distant date, without clicking
month by month.

Months and years with no day within `min` and `max` are disabled. `Esc` or a
new click on the open button returns to the days without changing anything.
With `range`, the first end already chosen stays marked after changing the
month or year.

## Datas indisponíveis

`min` e `max` cortam as pontas, mas não abrem buracos no meio: um feriado, um
dia já reservado, uma data sem vaga. Para isso, `isDateDisabled` recebe uma
função, só em JS (não é um atributo HTML), chamada com cada dia do mês
mostrado. Um dia em que ela retorna `true` fica com `aria-disabled`, não pode
ser escolhido e ganha um traço, que não depende só da opacidade — a mesma
opacidade de um dia fora de `min`/`max` não bastaria para diferenciar os dois
motivos.

Com `editable`, digitar ou colar uma data que cai num dia marcado por
`isDateDisabled` também deixa o campo inválido, com a mensagem de
`unavailable-date-text`, própria desse caso e diferente da de `range-error-text`
(fora de `min`/`max`). Isso vale mesmo sem o calendário aberto, já que digitar
contorna o clique bloqueado. Com `range`, a checagem é só nas duas pontas: um
período pode atravessar um dia indisponível no meio, do mesmo jeito que já
atravessa um fim de semana ou um feriado sem problema — só a data escolhida
como início ou fim é que não pode cair num dia indisponível. Com
`range-fields="two"`, só a caixa da ponta em questão fica marcada.

Como não é um atributo, a função é atribuída por JS, depois que o elemento
existe. Compare as datas pelas partes locais: `toISOString()` lê UTC e, a
leste de Greenwich, cai no dia anterior.

```html
<lui-date-picker id="check-in" label="Check-in"></lui-date-picker>

<script>
  const unavailable = new Set(['2026-01-18', '2026-01-19', '2026-01-25']);

  const iso = (date) =>
    [
      date.getFullYear(),
      String(date.getMonth() + 1).padStart(2, '0'),
      String(date.getDate()).padStart(2, '0'),
    ].join('-');

  document.querySelector('#check-in').isDateDisabled = (date) =>
    unavailable.has(iso(date));
</script>
```

A função roda a cada renderização, uma vez por dia do mês na tela. Mantenha-a
rápida: uma consulta a um `Set`, não uma requisição.

</Lang>

## Unavailable dates

`min` and `max` cut the ends, but do not open holes in the middle: a holiday, a
day already booked, a date with no availability. For that, `isDateDisabled`
receives a function, only in JS (it is not an HTML attribute), called with each
day of the shown month. A day for which it returns `true` gets `aria-disabled`,
cannot be chosen and gains a dash, which does not depend only on opacity — the
same opacity as a day outside `min`/`max` would not be enough to tell the two
reasons apart.

With `editable`, typing or pasting a date that falls on a day marked by
`isDateDisabled` also leaves the field invalid, with the message from
`unavailable-date-text`, specific to that case and different from
`range-error-text` (outside `min`/`max`). This applies even without the
calendar open, since typing bypasses the blocked click. With `range`, the check
is only on the two ends: a period can cross an unavailable day in the middle,
the same way it already crosses a weekend or a holiday without a problem — only
the date chosen as start or end cannot fall on an unavailable day. With
`range-fields="two"`, only the box of the end in question is marked.

Since it is not an attribute, the function is assigned through JS, after the
element exists. Compare dates by their local parts: `toISOString()` reads UTC
and, east of Greenwich, falls on the previous day.

```html
<lui-date-picker id="check-in" label="Check-in"></lui-date-picker>

<script>
  const unavailable = new Set(['2026-01-18', '2026-01-19', '2026-01-25']);

  const iso = (date) =>
    [
      date.getFullYear(),
      String(date.getMonth() + 1).padStart(2, '0'),
      String(date.getDate()).padStart(2, '0'),
    ].join('-');

  document.querySelector('#check-in').isDateDisabled = (date) =>
    unavailable.has(iso(date));
</script>
```

The function runs on every render, once per day of the month on screen. Keep it
fast: a query to a `Set`, not a request.

</Lang>

## Idioma e início da semana

`locale` recebe uma tag BCP 47 e define o idioma do mês no cabeçalho, dos dias
da semana, dos nomes acessíveis dos dias e do texto do campo. O texto do campo
segue a convenção de cada idioma. A ordem de dia, mês e ano, a abreviação do mês
e a pontuação mudam conforme a `locale`:

| `locale` | Data               | Range                   |
| -------- | ------------------ | ----------------------- |
| `en-US`  | Oct 16, 2026       | Oct 16 – 21, 2026       |
| `en-GB`  | 16 Oct 2026        | 16 – 21 Oct 2026        |
| `pt-BR`  | 16 de out. de 2026 | 16 – 21 de out. de 2026 |
| `de-DE`  | 16. Okt. 2026      | 16.–21. Okt. 2026       |
| `pt-PT`  | 16/10/2026         | 16/10/2026 – 21/10/2026 |
| `ja-JP`  | 2026年10月16日     | 2026/10/16～2026/10/21  |

O campo pede ao navegador o mês abreviado, porque o mês escrito evita confusão:
`10/11/2026` é outubro nos Estados Unidos e novembro no Brasil. A maioria dos
idiomas escreve o mês, mas alguns, como `pt-PT` e `ja-JP`, usam números
mesmo assim. É a convenção desses idiomas, e lá a ordem dos campos não é
ambígua. A `locale` não altera o `value`, que fica em
ISO 8601.

Sem `locale`, o campo segue o `lang` do ancestral mais próximo, `<html>`
incluído, e sem nenhum `lang` usa `en-US`. Assim uma página com
`<html lang="pt-BR">` já mostra meses e dias em português. Se o navegador não
reconhecer a tag, o campo usa o idioma do navegador.

`first-day-of-week` define a primeira coluna do calendário. Nos Estados Unidos
e no Brasil a semana começa no domingo, e na maior parte da Europa começa na
segunda.

</Lang>

## Language and first day of week

`locale` receives a BCP 47 tag and defines the language of the month in the
header, of the days of the week, of the accessible names of the days and of the
field text. The field text follows the convention of each language. The order
of day, month and year, the month abbreviation and the punctuation change
according to the `locale`:

| `locale` | Date               | Range                   |
| -------- | ------------------ | ----------------------- |
| `en-US`  | Oct 16, 2026       | Oct 16 – 21, 2026       |
| `en-GB`  | 16 Oct 2026        | 16 – 21 Oct 2026        |
| `pt-BR`  | 16 de out. de 2026 | 16 – 21 de out. de 2026 |
| `de-DE`  | 16. Okt. 2026      | 16.–21. Okt. 2026       |
| `pt-PT`  | 16/10/2026         | 16/10/2026 – 21/10/2026 |
| `ja-JP`  | 2026年10月16日     | 2026/10/16～2026/10/21  |

The field asks the browser for the abbreviated month, because a written month
avoids confusion: `10/11/2026` is October in the United States and November in
Brazil. Most languages write the month, but some, such as `pt-PT` and `ja-JP`,
use numbers anyway. That is the convention of those languages, and there the
order of the fields is not ambiguous. The `locale` does not change `value`,
which stays in ISO 8601.

Without `locale`, the field follows the `lang` of its closest ancestor,
`<html>` included, and with no `lang` at all it uses `en-US`. So a page with
`<html lang="pt-BR">` already shows months and days in Portuguese. If the
browser does not recognize the tag, the field uses the browser language.

`first-day-of-week` defines the first column of the calendar. In the United
States and Brazil the week starts on Sunday, and in most of Europe it starts on
Monday.

</Lang>

## Integração com formulários

O `lui-date-picker` é um form-associated custom element. O valor entra no
`FormData` do form com o `name` do campo, em ISO 8601.

A validação usa `ElementInternals.setValidity()`, como nos elementos nativos.
Com `required` e sem data, o campo reporta `valueMissing`. Um `value` que começa
antes de `min` reporta `rangeUnderflow`, e um que termina depois de `max`
reporta `rangeOverflow`. Cada caso tem a sua mensagem:

| Validade                           | Quando                                                       | Mensagem                |
| ---------------------------------- | ------------------------------------------------------------ | ----------------------- |
| `valueMissing`                     | `required` e sem data                                        | `error-text`            |
| `rangeUnderflow` / `rangeOverflow` | A data começa antes de `min` ou termina depois de `max`      | `range-error-text`      |
| `badInput`                         | Com `editable`, o texto está incompleto ou a data não existe | `bad-input-text`        |
| `badInput`                         | Com `editable range`, a data final vem antes da inicial      | `range-order-text`      |
| `customError`                      | Uma ponta cai num dia de `isDateDisabled`                    | `unavailable-date-text` |

</Lang>

## Form integration

`lui-date-picker` is a form-associated custom element. The value enters the form
`FormData` with the field `name`, in ISO 8601.

Validation uses `ElementInternals.setValidity()`, as in native elements. With
`required` and no date, the field reports `valueMissing`. A `value` that starts
before `min` reports `rangeUnderflow`, and one that ends after `max` reports
`rangeOverflow`. Each case has its own message:

| Validity                           | When                                                               | Message                 |
| ---------------------------------- | ------------------------------------------------------------------ | ----------------------- |
| `valueMissing`                     | `required` and no date                                             | `error-text`            |
| `rangeUnderflow` / `rangeOverflow` | The date starts before `min` or ends after `max`                   | `range-error-text`      |
| `badInput`                         | With `editable`, the text is incomplete or the date does not exist | `bad-input-text`        |
| `badInput`                         | With `editable range`, the end date comes before the start         | `range-order-text`      |
| `customError`                      | An end falls on a day of `isDateDisabled`                          | `unavailable-date-text` |

</Lang>

## Acessibilidade

O calendário segue o padrão
[Date Picker Dialog](https://www.w3.org/WAI/ARIA/apg/patterns/dialog-modal/examples/datepicker-dialog/)
do WAI-ARIA APG: um diálogo não modal com os dias numa `grid`.

### Nome do campo

`label` é obrigatório. Quando não houver rótulo visível, use `aria-label` no
lugar dele. Sem os dois, o campo fica sem nome acessível: sem `editable`, o nome
é só a data ou o placeholder; com `editable`, só resta o placeholder, que
leitores de tela não anunciam de forma confiável. Nesse caso, o componente
avisa no console uma vez por campo.
Com `range`, use um rótulo que descreva o período, como "Estadia" ou "Período
do relatório".

### Teclado no campo

| Tecla            | Ação                                                        |
| ---------------- | ----------------------------------------------------------- |
| `Enter`, `Space` | No botão, abre ou fecha o calendário                        |
| `↓`, `↑`         | No botão, abre o calendário no dia selecionado ou em hoje   |
| `Alt` + `↓`      | Com `editable`, na caixa de texto, abre o calendário        |
| `Esc`            | Com o calendário aberto, fecha sem alterar                  |
| `0`–`9`          | Com `editable`, digita a data; a máscara põe os separadores |

Com `editable`, as setas da caixa de texto movem o cursor, por isso o
calendário abre com `Alt` + `↓`, como num `<select>` nativo.

### Teclado no calendário

| Tecla                        | Ação                                                         |
| ---------------------------- | ------------------------------------------------------------ |
| `←` `→`                      | Dia anterior / seguinte                                      |
| `↑` `↓`                      | Mesma coluna na semana anterior / seguinte                   |
| `Home` `End`                 | Início / fim da semana                                       |
| `Page Up` `Page Down`        | Mês anterior / seguinte                                      |
| `Shift` + `Page Up` / `Down` | Ano anterior / seguinte                                      |
| `Enter`, `Space`             | Seleciona o dia focado e fecha                               |
| `Tab`                        | Passa pelos botões do cabeçalho e pela grade; ao sair, fecha |
| `Esc`                        | Fecha sem alterar                                            |

Com `range`, o primeiro `Enter` marca uma ponta e o segundo marca a outra.
Entre os dois, o intervalo acompanha o foco. `Esc` descarta a seleção
incompleta e mantém o valor anterior. Essa prévia é só visual: até o segundo
`Enter`, só o primeiro dia escolhido tem `aria-selected` e
`range-start-day-text` no nome, para que o dia com foco não seja anunciado
como fim do período antes de ser escolhido. A prévia não para num dia marcado
por `isDateDisabled`: ela fica no último dia que pode ser escolhido.

### Teclado nas grades de mês e ano

| Tecla                 | Ação                                                                 |
| --------------------- | -------------------------------------------------------------------- |
| `←` `→`               | Mês ou ano anterior / seguinte                                       |
| `↑` `↓`               | Mesma coluna na linha anterior / seguinte                            |
| `Home` `End`          | Início / fim da linha                                                |
| `Page Up` `Page Down` | Ano anterior / seguinte nos meses; doze anos antes / depois nos anos |
| `Enter`, `Space`      | Escolhe e volta aos dias                                             |
| `Esc`                 | Volta aos dias sem alterar; um segundo `Esc` fecha o calendário      |

Ao abrir uma grade, o foco vai para o mês ou o ano do dia ativo. Ao voltar aos
dias, ele vai para o dia ativo.

### Foco

- Ao abrir, o foco vai para o dia selecionado ou, sem valor, para o dia de hoje.
  As setas e a navegação de mês param nos limites de `min` e `max`.
- A grade tem um único ponto de tabulação, inclusive com dois meses lado a lado.
- Ao fechar com `Esc` ou ao escolher um dia, o foco volta ao controle que abriu
  o calendário: o campo ou, com `editable`, o botão do calendário.
- O calendário fecha com `Tab` para fora dele ou com um clique fora. O diálogo
  tem `aria-modal="false"` e não prende o foco.
- Dentro de um modal, `Esc` fecha só o calendário, não o modal.
- Com `open` no HTML, o calendário aparece sem tirar o foco da página.
- Com `editable`, o botão do calendário tem anel de foco próprio, para não se
  confundir com o foco na caixa de texto.

### O que o leitor de tela anuncia

| Elemento              | Anúncio                                                                                                                                                                                                                                                                                |
| --------------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Campo                 | `<button aria-haspopup="dialog">` nomeado pelo rótulo e pela data exibida, com `aria-expanded`                                                                                                                                                                                         |
| Range em dois campos  | `role="group"` nomeado pelo rótulo, com duas caixas nomeadas por `start-label` e `end-label`, cada uma descrita pelo formato                                                                                                                                                           |
| Campo com `editable`  | `<input inputmode="numeric">` nomeado pelo rótulo e descrito pelo formato (`dd / mm / yyyy`), pelo hint ou pelo erro                                                                                                                                                                   |
| Botão do calendário   | `dialog-label` seguido da data escolhida: `Choose date, Jan 16, 2026`                                                                                                                                                                                                                  |
| Calendário            | Diálogo nomeado por `dialog-label`                                                                                                                                                                                                                                                     |
| Mês                   | Uma região `aria-live="polite"`, anunciada ao trocar de mês; com `range`, os dois meses juntos                                                                                                                                                                                         |
| Primeira ponta        | Com `range`, outra região `aria-live="polite"` anuncia `range-start-text` depois da primeira escolha                                                                                                                                                                                   |
| Período escolhido     | Ao fechar, o foco volta ao campo, nomeado com o período em ordem: `Stay Jan 12 – 20, 2026`                                                                                                                                                                                             |
| Dias da semana        | Nome completo ("Sunday"), mesmo quando a tela mostra só "S"                                                                                                                                                                                                                            |
| Dia                   | Data por extenso: "Friday, January 16, 2026". A própria célula (`<td role="gridcell">`) recebe o foco, sem botão dentro                                                                                                                                                                |
| Hoje                  | `aria-current="date"`                                                                                                                                                                                                                                                                  |
| Dia selecionado       | `aria-selected="true"` na célula do dia, que é o elemento com foco, e o estado no nome: "Friday, January 16, 2026, selected"; com `range`, "start of period", "in period" ou "end of period". | Dia indisponível      | `aria-disabled="true"` e `unavailable-day-text` no nome: "Sunday, January 18, 2026, unavailable"                                                                                                                                                                                       |

## Accessibility

The calendar follows the WAI-ARIA APG
[Date Picker Dialog](https://www.w3.org/WAI/ARIA/apg/patterns/dialog-modal/examples/datepicker-dialog/)
pattern: a non-modal dialog with the days in a `grid`.

### Field name

`label` is required. When there is no visible label, use `aria-label` in its
place. Without both, the field has no accessible name: without `editable`, the
name is only the date or the placeholder; with `editable`, only the placeholder
remains, which screen readers do not announce reliably. In that case, the
component warns in the console once per field.
With `range`, use a label that describes the period, such as "Stay" or "Report
period".

### Keyboard in the field

| Key              | Action                                                            |
| ---------------- | ----------------------------------------------------------------- |
| `Enter`, `Space` | On the button, opens or closes the calendar                       |
| `↓`, `↑`         | On the button, opens the calendar on the selected day or on today |
| `Alt` + `↓`      | With `editable`, in the text box, opens the calendar              |
| `Esc`            | With the calendar open, closes without changing                   |
| `0`–`9`          | With `editable`, types the date; the mask adds the separators     |

With `editable`, the text box arrows move the cursor, so the calendar opens
with `Alt` + `↓`, as in a native `<select>`.

### Keyboard in the calendar

| Key                          | Action                                                           |
| ---------------------------- | ---------------------------------------------------------------- |
| `←` `→`                      | Previous / next day                                              |
| `↑` `↓`                      | Same column in the previous / next week                          |
| `Home` `End`                 | Start / end of the week                                          |
| `Page Up` `Page Down`        | Previous / next month                                            |
| `Shift` + `Page Up` / `Down` | Previous / next year                                             |
| `Enter`, `Space`             | Selects the focused day and closes                               |
| `Tab`                        | Goes through the header buttons and the grid; on leaving, closes |
| `Esc`                        | Closes without changing                                          |

With `range`, the first `Enter` marks one end and the second marks the other.
Between the two, the range follows the focus. `Esc` discards the incomplete
selection and keeps the previous value. That preview is only visual: until the
second `Enter`, only the first chosen day has `aria-selected` and
`range-start-day-text` in the name, so that the focused day is not announced as
the end of the period before being chosen. The preview does not stop on a day
marked by `isDateDisabled`: it stays on the last day that can be chosen.

### Keyboard in the month and year grids

| Key                   | Action                                                                       |
| --------------------- | ---------------------------------------------------------------------------- |
| `←` `→`               | Previous / next month or year                                                |
| `↑` `↓`               | Same column in the previous / next row                                       |
| `Home` `End`          | Start / end of the row                                                       |
| `Page Up` `Page Down` | Previous / next year in the months; twelve years before / after in the years |
| `Enter`, `Space`      | Chooses and returns to the days                                              |
| `Esc`                 | Returns to the days without changing; a second `Esc` closes the calendar     |

When a grid opens, focus goes to the month or year of the active day. When
returning to the days, it goes to the active day.

### Focus

- On open, focus goes to the selected day or, without a value, to today.
  The arrows and the month navigation stop at the `min` and `max` limits.
- The grid has a single tab stop, including with two months side by side.
- When closing with `Esc` or choosing a day, focus returns to the control that
  opened the calendar: the field or, with `editable`, the calendar button.
- The calendar closes with `Tab` out of it or with a click outside. The dialog
  has `aria-modal="false"` and does not trap focus.
- Inside a modal, `Esc` closes only the calendar, not the modal.
- With `open` in the HTML, the calendar appears without taking focus from the page.
- With `editable`, the calendar button has its own focus ring, so it is not
  confused with the focus in the text box.

| Calendar button             | `dialog-label` followed by the chosen date: `Choose date, Jan 16, 2026`                                                                                                                                                                                                                            |
| Calendar                    | Dialog named by `dialog-label`                                                                                                                                                                                                                                                                     |
| Month                       | An `aria-live="polite"` region, announced on month change; with `range`, the two months together                                                                                                                                                                                                   |
| First end                   | With `range`, another `aria-live="polite"` region announces `range-start-text` after the first choice                                                                                                                                                                                              |
| Chosen period               | On close, focus returns to the field, named with the period in order: `Stay Jan 12 – 20, 2026`                                                                                                                                                                                                     |
| Days of the week            | Full name ("Sunday"), even when the screen shows only "S"                                                                                                                                                                                                                                          |
| Day                         | Full date: "Friday, January 16, 2026". The cell itself (`<td role="gridcell">`) receives focus, with no button inside                                                                                                                                                                              |
| Today                       | `aria-current="date"`                                                                                                                                                                                                                                                                              |
| Selected day                | `aria-selected="true"` in the day cell, which is the focused element, and the state in the name: "Friday, January 16, 2026, selected"; with `range`, "start of period", "in period" or "end of period". VoiceOver does not announce `aria-selected` in a `gridcell`, so the name repeats the state |
| Unavailable day             | `aria-disabled="true"` and `unavailable-day-text` in the name: "Sunday, January 18, 2026, unavailable"                                                                                                                                                                                             |
| Day outside the range       | `aria-disabled="true"`: reachable by keyboard, but cannot be chosen                                                                                                                                                                                                                                |
| Month buttons               | `previous-month-label` and `next-month-label`; `aria-disabled` at the `min` and `max` limits                                                                                                                                                                                                       |
| Month and year in the title | Two buttons with `aria-expanded`: "January, choose month" and "2026, choose year". In the open grid, each month or year is a `gridcell`, with `aria-selected` and the state in the name as in the days; the month region announces the year or the twelve years on screen                          |
| Error                       | `aria-invalid`, the case message linked by `aria-describedby`; required: with `editable`, `aria-required`, and without it, `required-text` in the description                                                                                                                                      |

The format is part of the field description, not only of the placeholder,
because the placeholder disappears when the person starts typing and can be
replaced by another text. Without `hint`, the description points only to the
text below the field, which already shows the format, so that it is read once.

The field without `editable` is a `<button>`, which does not accept
`aria-required`. With `required`, a hidden text (`required-text`, "Required" by
default) enters the button description, before the message, so that the field
is announced as required from the start. On submitting the empty form,
`valueMissing` applies, with `error-text`.
