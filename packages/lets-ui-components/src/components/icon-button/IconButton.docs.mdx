# Icon Button

A compact button that shows only an icon, with no visible text. The action name comes from `aria-label`.

<Lang lang="pt-BR">
## Quando usar

Use o Icon Button quando o espaço é curto e o ícone é reconhecível sem texto: "mais opções" numa linha de tabela, "editar" num card, as ações de uma toolbar.

- Quando há espaço para texto, ou o ícone sozinho é ambíguo, use o [Button](?path=/docs/actionable-button--docs) com o ícone no slot `prefix`. Um texto visível é sempre mais claro que um ícone.
- Para fechar um Alert, um Modal ou um Drawer, use o [Close Button](?path=/docs/actionable-close-button--docs), que já vem com o ícone e o nome acessível.
- Para navegar para outra página, use o Button com `href` ou o [componente Link](?path=/docs/navigation-link--docs). O Icon Button é sempre um botão, e um controle que navega deve ser anunciado como link.

</Lang>

<Lang lang="en-US">
## When to use

Use Icon Button when space is short and the icon is recognizable without text: "more options" in a table row, "edit" in a card, the actions of a toolbar.

- When there is room for text, or the icon alone is ambiguous, use [Button](?path=/docs/actionable-button--docs) with the icon in the `prefix` slot. Visible text is always clearer than an icon.
- To close an Alert, a Modal or a Drawer, use [Close Button](?path=/docs/actionable-close-button--docs), which already comes with the icon and the accessible name.
- To navigate to another page, use Button with `href` or the [Link component](?path=/docs/navigation-link--docs). Icon Button is always a button, and a control that navigates must be announced as a link.

</Lang>

<Lang lang="pt-BR">
## Nome acessível

**`aria-label` é obrigatório.** Sem texto visível, ele é o único nome que o leitor de tela anuncia. Sem ele, o botão é lido só como "botão". Descreva a ação, não o ícone: `aria-label="Excluir arquivo"`, não `aria-label="Lixeira"`. Quando houver vários Icon Buttons na mesma tela, torne cada nome distinto (`"Excluir arquivo"`, `"Excluir pasta"`).

Marque o SVG do slot com `aria-hidden="true"`: ele é decorativo, já que o nome vem do `aria-label`.

</Lang>

<Lang lang="en-US">
## Accessible name

**`aria-label` is required.** With no visible text, it is the only name the screen reader announces. Without it, the button is read only as "button". Describe the action, not the icon: `aria-label="Delete file"`, not `aria-label="Trash"`. When there are several Icon Buttons on the same screen, make each name distinct (`"Delete file"`, `"Delete folder"`).

Mark the slot SVG with `aria-hidden="true"`: it is decorative, since the name comes from `aria-label`.

</Lang>

<Lang lang="pt-BR">
## Com Tooltip

Quem enxerga o ícone também precisa saber o que ele faz. Envolva o Icon Button num [Tooltip](?path=/docs/content-tooltip--docs) para mostrar o nome da ação no hover e no foco.

O texto do tooltip vira a descrição do botão (`aria-description`), não o nome: o `aria-label` continua obrigatório. O botão continua sendo a única parada de tabulação.

Use no tooltip o mesmo texto do `aria-label`, para que quem enxerga veja o nome que o leitor de tela anuncia. Quando o texto repete o nome, o Tooltip não o define como descrição, e o leitor de tela anuncia "Excluir item, botão" uma vez só. Um tooltip com outro texto, como um complemento ("Remove o item da lista"), vira a descrição do botão.

</Lang>

<Lang lang="en-US">
## With Tooltip

People who see the icon also need to know what it does. Wrap the Icon Button in a [Tooltip](?path=/docs/content-tooltip--docs) to show the action name on hover and focus.

The tooltip text becomes the button description (`aria-description`), not the name: `aria-label` is still required. The button remains the only tab stop.

Use the same text as `aria-label` in the tooltip, so that sighted people see the name the screen reader announces. When the text repeats the name, Tooltip does not set it as a description, and the screen reader announces "Delete item, button" only once. A tooltip with different text, such as a complement ("Removes the item from the list"), becomes the button description.

</Lang>

## Disabled

`disabled` desabilita o botão: ele fica opaco, não responde a clique e sai da ordem de tabulação. Como não recebe foco, quem navega por teclado ou leitor de tela não chega até ele. Dentro de um Tooltip, o foco vai para o wrapper do tooltip, que mostra o texto mas é anunciado como grupo, sem o papel de botão nem o estado indisponível. Se a pessoa precisa saber por que a ação está indisponível, explique o motivo num texto visível.

</Lang>

<Lang lang="en-US">
## Disabled

`disabled` disables the button: it becomes opaque, does not respond to clicks and leaves the tab order. Because it cannot receive focus, people navigating with a keyboard or screen reader never reach it. Inside a Tooltip, focus goes to the tooltip wrapper, which shows the text but is announced as a group, without the button role or the unavailable state. If people need to know why the action is unavailable, explain the reason in visible text.

</Lang>

<Lang lang="pt-BR">
## Estado de componentes acionados

Icon Buttons costumam abrir menus e painéis ou alternar formatações, como o botão de "mais opções" ou o de negrito numa toolbar. Informe o estado com `aria-expanded`, `aria-haspopup` ou `aria-pressed` no próprio `<lui-icon-button>`. O componente leva esses atributos, e o `aria-label`, ao `<button>` interno, que é o que o leitor de tela anuncia, e os remove do elemento externo: lá eles criariam um segundo nó, sem papel, na árvore de acessibilidade.

Como o atributo sai do `<lui-icon-button>`, seletores como `lui-icon-button[aria-pressed="true"]` e `getAttribute('aria-pressed')` não o encontram. Leia a propriedade (`button.ariaPressed`). Para limpar um estado, use um valor explícito (`aria-pressed="false"`) ou a propriedade com `null`: remover um atributo que o componente já consumiu não tem efeito.

Como `slot="trigger"` de um Modal, de um Drawer ou de um Dropdown Menu, o botão recebe esse estado do próprio componente e anuncia "recolhido" ou "expandido" sem configuração adicional. O `aria-controls` não é repassado: um ID não pode ser referenciado entre shadow roots diferentes.

</Lang>

<Lang lang="en-US">
## State of triggered components

Icon Buttons often open menus and panels or toggle formatting, such as the "more options" button or the bold button in a toolbar. Report the state with `aria-expanded`, `aria-haspopup` or `aria-pressed` on the `<lui-icon-button>` itself. The component moves those attributes, and `aria-label`, to the internal `<button>`, which is what the screen reader announces, and removes them from the outer element: there they would create a second, role-less node in the accessibility tree.

Because the attribute leaves the `<lui-icon-button>`, selectors such as `lui-icon-button[aria-pressed="true"]` and `getAttribute('aria-pressed')` do not find it. Read the property (`button.ariaPressed`) instead. To clear a state, use an explicit value (`aria-pressed="false"`) or the property with `null`: removing an attribute the component has already consumed has no effect.

As the `slot="trigger"` of a Modal, a Drawer or a Dropdown Menu, the button receives that state from the component itself and announces "collapsed" or "expanded" with no extra configuration. `aria-controls` is not forwarded: an ID cannot be referenced across different shadow roots.

</Lang>

## Botão alternável

Para ligar e desligar uma opção, como um filtro ou uma formatação, use `aria-pressed="true"` ou `"false"` e troque o valor a cada clique. Pressionado, o botão ganha o fundo de container neutro. Hover, foco e `disabled` continuam funcionando sobre o estado pressionado. Em modo de alto contraste (`forced-colors`), o botão pressionado usa as cores de destaque do sistema e ganha um anel interno.

Mantenha o mesmo `aria-label` nos dois estados: o leitor de tela anuncia "pressionado" ou "não pressionado", e um nome que muda com o estado confunde. `aria-pressed="mixed"` não tem estilo próprio e aparece como não pressionado.

</Lang>

<Lang lang="en-US">
## Toggle button

To turn an option on and off, such as a filter or a formatting, use `aria-pressed="true"` or `"false"` and toggle the value on every click. When pressed, the button gets the neutral container background. Hover, focus and `disabled` keep working on top of the pressed state. In high contrast mode (`forced-colors`), the pressed button uses the system highlight colors and gains an inner ring.

Keep the same `aria-label` in both states: the screen reader announces "pressed" or "not pressed", and a name that changes with the state is confusing. `aria-pressed="mixed"` has no style of its own and appears as not pressed.

</Lang>

## Acessibilidade

- Renderiza um `<button>` nativo: navegável com `Tab`, acionado com `Enter` ou `Espaço`.
- O nome acessível vem só do `aria-label`. O ícone é decorativo e não entra no nome.
- `aria-expanded`, `aria-haspopup` e `aria-pressed` definidos no `<lui-icon-button>`, e a descrição de um Tooltip em volta dele, são repassados ao `<button>` interno. O elemento externo não tem papel e não carrega esses atributos para o leitor de tela.
- Os dois tamanhos atendem à área mínima de 24px da WCAG 2.5.8.
- O foco continua visível em modo de alto contraste (`forced-colors`), com um contorno do sistema no lugar do anel.
- Com `disabled`, o botão sai da ordem de tabulação.

### Responsabilidades de quem usa

- Defina um `aria-label` que descreva a ação, distinto dos outros Icon Buttons da tela.
- Marque o SVG com `aria-hidden="true"`.
- Mostre o nome da ação para quem enxerga, com um Tooltip, quando o ícone não for óbvio.
- Para navegação, use um link, não o Icon Button.

</Lang>

<Lang lang="en-US">
## Accessibility

- Renders a native `<button>`: reachable with `Tab`, triggered with `Enter` or `Space`.
- The accessible name comes only from `aria-label`. The icon is decorative and does not enter the name.
- `aria-expanded`, `aria-haspopup` and `aria-pressed` set on the `<lui-icon-button>`, and the description of a Tooltip around it, are forwarded to the internal `<button>`. The outer element has no role and does not carry those attributes to the screen reader.
- Both sizes meet the 24px minimum target of WCAG 2.5.8.
- Focus stays visible in high contrast mode (`forced-colors`), with a system outline in place of the ring.
- With `disabled`, the button leaves the tab order.

### Consumer responsibilities

- Set an `aria-label` that describes the action, distinct from the other Icon Buttons on the screen.
- Mark the SVG with `aria-hidden="true"`.
- Show the action name to sighted people, with a Tooltip, when the icon is not obvious.
- For navigation, use a link, not Icon Button.

</Lang>
