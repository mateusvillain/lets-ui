## Uso

### Web Component

```html
<lui-modal title="Título" size="md" trigger-label="Open modal">
  <p>Conteúdo do modal</p>
  <lui-button
    slot="actions"
    variant="secondary"
    label="Cancelar"
    data-modal-close
  ></lui-button>
  <lui-button slot="actions" label="Confirmar"></lui-button>
</lui-modal>
```

### Textos acessíveis

O botão de fechar usa `close-label` como `aria-label` (padrão: `"Close modal"`). Troque-o para o idioma do projeto.

```html
<lui-modal title="Título" close-label="Fechar modal"></lui-modal>
```

### Fechar por uma ação

Marque com `data-modal-close` o botão que só fecha o modal — um "Cancelar", por exemplo. Funciona no slot `actions` e no conteúdo, num elemento nativo ou num `lui-button`, e também quando o clique vem de algo dentro do elemento marcado.

```html
<lui-modal title="Título">
  <p>Conteúdo</p>
  <lui-button
    slot="actions"
    variant="secondary"
    label="Cancelar"
    data-modal-close
  ></lui-button>
  <lui-button slot="actions" label="Confirmar"></lui-button>
</lui-modal>
```

- O atributo fecha o `lui-modal` mais próximo acima dele: dentro de um `lui-modal` aninhado, fecha só esse.
- No slot `trigger`, o atributo é ignorado.
- Não fecha quando o clique passa por um controle com `aria-disabled="true"` (um `lui-button` em `loading`) ou quando um handler chama `event.preventDefault()`.
- Ações que fazem algo antes de fechar (como "Confirmar") chamam `closeModal()` no próprio handler.

### Contrato ARIA do trigger

O trigger recebe `aria-haspopup="dialog"` e `aria-expanded`, que acompanha o estado aberto/fechado. É isso que o leitor de tela anuncia.

- **Trigger padrão** (o botão gerado por `trigger-label`): também recebe `aria-controls`, porque vive no mesmo shadow root do dialog e o IDREF resolve.
- **Trigger customizado** (`slot="trigger"`): não recebe `aria-controls`. O dialog fica no shadow root do `lui-modal`, e nem um IDREF nem `ariaControlsElements` alcançam o interior de outro shadow root a partir do light DOM — o navegador descarta a referência. A relação trigger → dialog fica ausente da árvore de acessibilidade, por limitação da plataforma. O estado expandido continua anunciado.

### Foco

Ao abrir, o foco vai para o dialog. Ao fechar — por Escape, botão de fechar, clique no backdrop, elemento com `data-modal-close`, `closeModal()` ou removendo `open` — o foco volta ao elemento que estava focado quando o dialog abriu: o trigger padrão, o trigger do slot ou o botão externo que alterou `open`.

- Se esse elemento saiu da página, o foco vai para o trigger do componente. Sem trigger (`hide-trigger`), o foco não é movido.
- Se algo já moveu o foco para fora do `lui-modal` antes de fechar, o componente não o devolve.
- No Safari, clicar com o mouse não foca botões. Um botão externo que abre o componente por clique (com `hide-trigger`) não é registrado como origem, e o foco não volta para ele. Os triggers do próprio componente não têm essa limitação: são o destino de reserva.
- Remover o componente da página enquanto está aberto também devolve o foco.

### Diálogos empilhados

Com diálogos abertos um sobre o outro (um Modal aberto de dentro de um Drawer, por exemplo), Escape fecha só o do topo. O foco volta ao trigger dentro do diálogo que continua aberto; um segundo Escape fecha o de baixo.

Um componente dentro do diálogo que usa Escape — um Dropdown Menu aberto, o tooltip do botão de copiar de um Code Block — consome a tecla: Escape fecha esse componente, e o diálogo continua aberto.

### Classe CSS

```html
<div class="modal modal--md" role="dialog" aria-modal="true">
  <div class="modal__header">
    <span class="modal__title">Título</span>
    <button class="modal__close" aria-label="Fechar">×</button>
  </div>
  <div class="modal__body">Conteúdo do modal</div>
  <div class="modal__footer">
    <button class="btn btn--secondary btn--lg">Cancelar</button>
    <button class="btn btn--primary btn--lg">Confirmar</button>
  </div>
</div>
```

## Usage

### Web Component

```html
<lui-modal title="Title" size="md" trigger-label="Open modal">
  <p>Modal content</p>
  <lui-button
    slot="actions"
    variant="secondary"
    label="Cancel"
    data-modal-close
  ></lui-button>
  <lui-button slot="actions" label="Confirm"></lui-button>
</lui-modal>
```

### Accessible texts

The close button uses `close-label` as its `aria-label` (default: `"Close modal"`). Change it to the project language.

```html
<lui-modal title="Title" close-label="Close modal"></lui-modal>
```

### Close by an action

Mark the button that only closes the modal — a "Cancel", for example — with `data-modal-close`. It works in the `actions` slot and in the content, on a native element or a `lui-button`, and also when the click comes from something inside the marked element.

```html
<lui-modal title="Title">
  <p>Content</p>
  <lui-button
    slot="actions"
    variant="secondary"
    label="Cancel"
    data-modal-close
  ></lui-button>
  <lui-button slot="actions" label="Confirm"></lui-button>
</lui-modal>
```

- The attribute closes the closest `lui-modal` above it: inside a nested `lui-modal`, only that one closes.
- In the `trigger` slot, the attribute is ignored.
- It does not close when the click passes through a control with `aria-disabled="true"` (a `lui-button` in `loading`) or when a handler calls `event.preventDefault()`.
- Actions that do something before closing (such as "Confirm") call `closeModal()` in their own handler.

### Trigger ARIA contract

The trigger receives `aria-haspopup="dialog"` and `aria-expanded`, which follows the open/closed state. That is what the screen reader announces.

- **Default trigger** (the button generated by `trigger-label`): also receives `aria-controls`, because it lives in the same shadow root as the dialog and the IDREF resolves.
- **Custom trigger** (`slot="trigger"`): does not receive `aria-controls`. The dialog lives in the shadow root of `lui-modal`, and neither an IDREF nor `ariaControlsElements` reach the inside of another shadow root from the light DOM — the browser discards the reference. The trigger → dialog relationship is absent from the accessibility tree, due to a platform limitation. The expanded state is still announced.

### Focus

On open, focus goes to the dialog. On close — via Escape, the close button, a backdrop click, an element with `data-modal-close`, `closeModal()` or by removing `open` — focus returns to the element that was focused when the dialog opened: the default trigger, the slot trigger or the external button that changed `open`.

- If that element left the page, focus goes to the component trigger. Without a trigger (`hide-trigger`), focus is not moved.
- If something already moved focus outside `lui-modal` before closing, the component does not return it.
- In Safari, clicking with the mouse does not focus buttons. An external button that opens the component by click (with `hide-trigger`) is not recorded as the origin, and focus does not return to it. The component's own triggers do not have this limitation: they are the fallback destination.
- Removing the component from the page while it is open also returns focus.

### Stacked dialogs

With dialogs open on top of each other (a Modal opened from inside a Drawer, for example), Escape closes only the top one. Focus returns to the trigger inside the dialog that remains open; a second Escape closes the one below.

A component inside the dialog that uses Escape — an open Dropdown Menu, the copy button tooltip of a Code Block — consumes the key: Escape closes that component, and the dialog remains open.
