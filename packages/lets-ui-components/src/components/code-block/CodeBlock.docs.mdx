# Code Block

Shows a code excerpt in a monospaced font, with a copy button, an optional label and line numbers. Designed for documentation pages. The code font comes from the `lui.brand.typography.font-family.code` token, which each brand can change.

<Lang lang="pt-BR">
## Quando usar

Use o Code Block para código que a pessoa vai ler ou copiar: comandos de instalação, exemplos de uso, arquivos de configuração.

- Para um termo de código no meio de uma frase, use `<code>` direto no texto. O Code Block é um bloco, não um trecho em linha.
- Dê um rótulo quando o contexto não for óbvio: o nome do arquivo na variante `default`, a linguagem ou o shell na `snippet`.
- Ligue a numeração quando o texto em volta citar linhas específicas. Em comandos de uma linha, ela só ocupa espaço.
</Lang>

<Lang lang="en-US">
## When to use

Use Code Block for code that people will read or copy: install commands, usage examples, configuration files.

- For a code term in the middle of a sentence, use `<code>` directly in the text. Code Block is a block, not an inline excerpt.
- Give it a label when the context is not obvious: the file name in the `default` variant, the language or the shell in `snippet`.
- Turn on line numbers when the surrounding text mentions specific lines. In single-line commands, they only take up space.
</Lang>

<Lang lang="pt-BR">
Texto solto é interpretado como HTML pelo navegador: `<` abriria uma tag. Para mostrar marcação, envolva o código em um `<script type="text/plain">`. O navegador não interpreta nem executa esse conteúdo, e o componente o lê exatamente como foi escrito.

```html
<lui-code-block label="Component.jsx">
  <script type="text/plain">
    <lui-button variant="primary" disabled>Save</lui-button>
  </script>
</lui-code-block>
```

A única coisa que não cabe nele é um `</script>`. Para código que contém essa tag, use um `<template>`. O template também é lido como texto, mas o navegador interpreta a marcação e a reescreve: quebras de linha dentro de uma tag somem e atributos booleanos viram `disabled=""`.

O componente acompanha mudanças no conteúdo feitas por script.
</Lang>

<Lang lang="en-US">
Plain text is interpreted as HTML by the browser: `<` would open a tag. To show markup, wrap the code in a `<script type="text/plain">`. The browser does not parse or run that content, and the component reads it exactly as written.

```html
<lui-code-block label="Component.jsx">
  <script type="text/plain">
    <lui-button variant="primary" disabled>Save</lui-button>
  </script>
</lui-code-block>
```

The only thing that does not fit in it is a `</script>`. For code that contains that tag, use a `<template>`. The template is also read as text, but the browser parses the markup and rewrites it: line breaks inside a tag disappear and boolean attributes become `disabled=""`.

The component follows content changes made by script.
</Lang>

## Realce de sintaxe

O Code Block colore o código quando recebe uma biblioteca de realce. O pacote não traz nenhuma: cada linguagem pesa, e quem não usa realce não deveria carregar parser nenhum. Em vez disso, o componente oferece um encaixe, `LuiCodeBlock.highlighter`, onde você liga a biblioteca uma vez para a página inteira.

## Syntax highlighting

Code Block colors the code when it receives a highlighting library. The package does not bring any: each language has a cost, and whoever does not use highlighting should not load any parser. Instead, the component offers a hook, `LuiCodeBlock.highlighter`, where you connect the library once for the whole page.

<Lang lang="pt-BR">
### 2. Conectar ao Code Block

No arquivo de entrada da aplicação, o mesmo onde você importa `@lets-ui/components`:

```js
import '@lets-ui/components';
import { LuiCodeBlock } from '@lets-ui/components';
import hljs from 'highlight.js/lib/core';
import javascript from 'highlight.js/lib/languages/javascript';
import css from 'highlight.js/lib/languages/css';
import xml from 'highlight.js/lib/languages/xml';
import bash from 'highlight.js/lib/languages/bash';

// Registre só as linguagens que a aplicação mostra.
hljs.registerLanguage('javascript', javascript);
hljs.registerLanguage('css', css);
hljs.registerLanguage('xml', xml);
hljs.registerLanguage('bash', bash);

// Liga o highlight.js a todos os Code Blocks da página.
LuiCodeBlock.highlighter = (code, language) =>
  hljs.getLanguage(language) ? hljs.highlight(code, { language }).value : null;
```

- **`highlight.js/lib/core`** carrega só o motor, e cada `registerLanguage` adiciona uma linguagem. Para protótipos, `import hljs from 'highlight.js'` traz todas de uma vez, ao custo de um bundle bem maior.
- **`hljs.getLanguage(language)`** confere se a linguagem foi registrada. Quando não foi, a função devolve `null` e o bloco aparece sem cor. Sem essa checagem, o highlight.js escreve um erro no console antes de falhar. O bloco também fica sem cor nesse caso, mas o console fica poluído.
- **A ordem não importa.** Registrar o highlighter antes ou depois de os blocos aparecerem na página dá no mesmo: os que já estão na tela são recoloridos.
</Lang>

<Lang lang="en-US">
### 2. Connect to Code Block

In the application entry file, the same one where you import `@lets-ui/components`:

```js
import '@lets-ui/components';
import { LuiCodeBlock } from '@lets-ui/components';
import hljs from 'highlight.js/lib/core';
import javascript from 'highlight.js/lib/languages/javascript';
import css from 'highlight.js/lib/languages/css';
import xml from 'highlight.js/lib/languages/xml';
import bash from 'highlight.js/lib/languages/bash';

// Register only the languages the application shows.
hljs.registerLanguage('javascript', javascript);
hljs.registerLanguage('css', css);
hljs.registerLanguage('xml', xml);
hljs.registerLanguage('bash', bash);

// Connects highlight.js to every Code Block on the page.
LuiCodeBlock.highlighter = (code, language) =>
  hljs.getLanguage(language) ? hljs.highlight(code, { language }).value : null;
```

- **`highlight.js/lib/core`** loads only the engine, and each `registerLanguage` adds a language. For prototypes, `import hljs from 'highlight.js'` brings all of them at once, at the cost of a much larger bundle.
- **`hljs.getLanguage(language)`** checks whether the language was registered. When it was not, the function returns `null` and the block appears without color. Without that check, highlight.js writes an error to the console before failing. The block also appears without color in that case, but the console gets polluted.
- **The order does not matter.** Registering the highlighter before or after the blocks appear on the page makes no difference: the ones already on screen are recolored.
</Lang>

### Cores

Com realce, o texto base passa de `text(caption)` para `text(body)`, para que os comentários, em `text(caption)`, fiquem como a camada mais discreta.

| Papel                | Classes do highlight.js                                                                       | Cor             |
| -------------------- | --------------------------------------------------------------------------------------------- | --------------- |
| Texto base           | (sem classe)                                                                                  | `text(body)`    |
| Comentário           | `hljs-comment`, `hljs-quote`                                                                  | `text(caption)` |
| Palavra-chave e meta | `hljs-keyword`, `hljs-meta`, `hljs-doctag`                                                    | `red-4`         |
| String               | `hljs-string`, `hljs-regexp`                                                                  | `blue-7`        |
| Número e literal     | `hljs-number`, `hljs-literal`, `hljs-symbol`                                                  | `blue-6`        |
| Função e classe      | `hljs-title`, `hljs-section`, seletores de id, classe, atributo e pseudo                      | `violet-5`      |
| Tag                  | `hljs-name`, `hljs-selector-tag`                                                              | `green-5`       |
| Atributo e variável  | `hljs-attr`, `hljs-attribute`, `hljs-property`, `hljs-variable`, `hljs-type`, `hljs-built_in` | `orange-5`      |

Todas as cores passam de 4,5:1 sobre o fundo do bloco, nos dois temas. Diffs (`hljs-addition` e `hljs-deletion`) ainda não têm cor: a paleta não tem fundos claros o bastante para manter o contraste do código por cima.

| Role                   | highlight.js classes                                                                          | Color           |
| ---------------------- | --------------------------------------------------------------------------------------------- | --------------- |
| Base text              | (no class)                                                                                    | `text(body)`    |
| Comment                | `hljs-comment`, `hljs-quote`                                                                  | `text(caption)` |
| Keyword and meta       | `hljs-keyword`, `hljs-meta`, `hljs-doctag`                                                    | `red-4`         |
| String                 | `hljs-string`, `hljs-regexp`                                                                  | `blue-7`        |
| Number and literal     | `hljs-number`, `hljs-literal`, `hljs-symbol`                                                  | `blue-6`        |
| Function and class     | `hljs-title`, `hljs-section`, id, class, attribute and pseudo selectors                       | `violet-5`      |

<Lang lang="pt-BR">
### Comportamento

- Sem highlighter registrado, sem `language`, ou quando o highlighter devolve `null` ou falha, o código aparece sem cor, como no protótipo.
- O botão de copiar e a propriedade `code` sempre usam o texto puro, sem as marcações do realce.
- O componente renderiza o HTML do highlighter como está. O highlight.js já escapa o código. Um highlighter próprio precisa escapar `<` e `&` antes de envolver os trechos.
</Lang>

<Lang lang="en-US">
### Behavior

- Without a registered highlighter, without `language`, or when the highlighter returns `null` or fails, the code appears without color, as in the prototype.
- The copy button and the `code` property always use the plain text, without the highlighting markup.
- The component renders the highlighter HTML as is. highlight.js already escapes the code. A custom highlighter must escape `<` and `&` before wrapping the excerpts.
</Lang>

<Lang lang="pt-BR">
### Outras bibliotecas

O encaixe aceita qualquer função que receba o código e a linguagem e devolva HTML. As cores, porém, só aparecem para as classes `hljs-*`.

| Biblioteca   | Cores dos tokens | Observação                                                                                         |
| ------------ | ---------------- | -------------------------------------------------------------------------------------------------- |
| highlight.js | Sim              | Recomendada.                                                                                       |
| lowlight     | Sim              | Usa o highlight.js por baixo. Devolve uma árvore: converta com `hast-util-to-html`.                |
| Prism        | Não              | Gera classes próprias (`token keyword`). O código aparece sem cor.                                 |
| starry-night | Não              | Gera classes `pl-*`. O código aparece sem cor.                                                     |
| Shiki        | Não              | Escreve as cores do tema dele direto em cada trecho. Fica colorido, mas ignora os tokens e o tema. |
</Lang>

<Lang lang="en-US">
### Other libraries

The hook accepts any function that receives the code and the language and returns HTML. The colors, however, only appear for the `hljs-*` classes.

| Library      | Token colors | Note                                                                                                               |
| ------------ | ------------ | ------------------------------------------------------------------------------------------------------------------ |
| highlight.js | Yes          | Recommended.                                                                                                       |
| lowlight     | Yes          | Uses highlight.js underneath. Returns a tree: convert it with `hast-util-to-html`.                                 |
| Prism        | No           | Generates its own classes (`token keyword`). The code appears without color.                                       |
| starry-night | No           | Generates `pl-*` classes. The code appears without color.                                                          |
| Shiki        | No           | Writes the colors of its theme directly into each excerpt. It stays colored, but ignores the tokens and the theme. |
</Lang>

## Classe CSS (sem Web Component)

A classe CSS reproduz o visual, mas o conteúdo fica todo a cargo de quem usa: escape `<` e `&` no código, escreva os números de linha à mão e deixe a indentação do código colada à margem dentro do `<pre>`. ## CSS class (without Web Component)

The CSS class reproduces the look, but the content is entirely up to the consumer: escape `<` and `&` in the code, write the line numbers by hand and keep the code indentation flush with the margin inside the `<pre>`. Copying depends on JavaScript, so the button does not exist in this version. If you build the button yourself, add `code-block--copy` to the block and, when the code has a single line, `code-block--single-line`: the body grows to fit the button and centers both. ## Acessibilidade

### Região do código

- O código fica em um `<pre>` com `role="region"`, que o leitor de tela anuncia como uma região nomeada. O nome vem do `label` (`Code snippet: main.js`), para que vários blocos na mesma página não apareçam com o mesmo nome na lista de regiões.
- Sem `label`, todo bloco se chamaria `Code snippet`. Nesse caso, ou quando dois blocos têm o mesmo `label`, dê a cada um um `aria-label` próprio.
- Quando as linhas não cabem, a região entra na ordem de foco: com o foco nela, as setas rolam o código (WCAG 2.1.1). Sem rolagem, ela não ocupa uma parada de `Tab`.
- As linhas longas rolam na horizontal em vez de quebrar. A WCAG 1.4.10 (Reflow) não se aplica quando quebrar a linha muda o sentido do conteúdo, e a indentação de código é um dos exemplos que o W3C cita.
- O código tem `translate="no"`: tradutores automáticos não traduzem palavras como `return` ou `class`, o que tornaria o código incorreto.

### Botão de copiar

- O botão é um `<button>` de 40×40px, acima do mínimo de 24×24px da WCAG 2.5.8. `Enter` e `Espaço` copiam.
- O nome acessível inclui o `label` (`Copy code: main.js`), para que os botões de copiar de blocos diferentes sejam distinguíveis numa lista de botões.
- A confirmação e o pedido de cópia manual são anunciados por uma região `role="status"` (WCAG 4.1.3), já que a dica visual não é lida. A região é esvaziada antes de cada mensagem, então uma segunda cópia seguida é anunciada como a primeira.
- Se o navegador recusar a cópia, o código fica selecionado e a mensagem indica o atalho, para que a pessoa consiga copiar mesmo assim.
- A dica segue a WCAG 1.4.13: `Esc` a fecha sem mover o ponteiro ou o foco, o ponteiro pode passar por cima dela sem que suma, e ela fica visível enquanto o botão está em foco ou sob o ponteiro.

### Visual

- Todas as cores, inclusive as do realce, passam de 4,5:1 sobre o fundo do bloco nos dois temas (WCAG 1.4.3). O realce é complementar: sem cor, o código é o mesmo (WCAG 1.4.1).
- O foco é visível no código e no botão (WCAG 2.4.7). No modo de cores forçadas, onde o navegador remove o anel de foco feito com sombra, um contorno na cor de destaque do sistema toma o lugar.
- Com `prefers-reduced-motion: reduce`, a dica aparece e some sem animação.
- Os números de linha têm `aria-hidden="true"` e não são selecionáveis: o leitor de tela lê só o código, e selecionar o texto não arrasta os números junto. Eles continuam alinhados ao código com os espaçamentos de texto da WCAG 1.4.12.
- O ícone do cabeçalho é decorativo. Se trocar pelo slot, coloque `aria-hidden="true"` no SVG.

## Accessibility

### Code region

- The code sits in a `<pre>` with `role="region"`, which the screen reader announces as a named region. The name comes from `label` (`Code snippet: main.js`), so that several blocks on the same page do not appear with the same name in the regions list.
- Without `label`, every block would be called `Code snippet`. In that case, or when two blocks have the same `label`, give each one its own `aria-label`.
- When the lines do not fit, the region enters the focus order: with focus on it, the arrows scroll the code (WCAG 2.1.1). Without scrolling, it does not take a `Tab` stop.
- Long lines scroll horizontally instead of wrapping. WCAG 1.4.10 (Reflow) does not apply when wrapping changes the meaning of the content, and code indentation is one of the examples the W3C cites.
- The code has `translate="no"`: automatic translators do not translate words such as `return` or `class`, which would make the code incorrect.

### Copy button

- The button is a 40×40px `<button>`, above the WCAG 2.5.8 minimum of 24×24px. `Enter` and `Space` copy.
- The accessible name includes the `label` (`Copy code: main.js`), so that the copy buttons of different blocks are distinguishable in a buttons list.
- The confirmation and the manual copy request are announced by a `role="status"` region (WCAG 4.1.3), since the visual tip is not read. The region is emptied before each message, so a second copy in a row is announced like the first.
- If the browser refuses the copy, the code stays selected and the message indicates the shortcut, so that the person can still copy it.
- The tip follows WCAG 1.4.13: `Esc` closes it without moving the pointer or the focus, the pointer can pass over it without it disappearing, and it stays visible while the button is focused or under the pointer.

### Visual

- All colors, including the highlighting ones, are above 4.5:1 over the block background in both themes (WCAG 1.4.3). Highlighting is complementary: without color, the code is the same (WCAG 1.4.1).
- Focus is visible on the code and on the button (WCAG 2.4.7). In forced colors mode, where the browser removes the shadow-based focus ring, an outline in the system accent color takes its place.
- With `prefers-reduced-motion: reduce`, the tip appears and disappears without animation.
- The line numbers have `aria-hidden="true"` and are not selectable: the screen reader reads only the code, and selecting the text does not drag the numbers along. They stay aligned with the code using the WCAG 1.4.12 text spacing.
- The header icon is decorative. If you replace it through the slot, add `aria-hidden="true"` to the SVG.

## Uso

```html
<lui-code-block label="Component.jsx" show-line-numbers>
  <script type="text/plain">
    <lui-button variant="primary" size="lg">Save</lui-button>
  </script>

<lui-code-block variant="snippet" label="bash">
  npm install @lets-ui/styles @lets-ui/components
```
