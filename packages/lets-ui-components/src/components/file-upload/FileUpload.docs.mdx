# File Upload

Campo para anexar arquivos a um formulário. Combina uma área de soltar (drag-and-drop) com um botão que abre o seletor nativo, lista os arquivos escolhidos com nome e tamanho, valida tipo, tamanho e quantidade localmente e permite remover cada arquivo.

# File Upload

Field for attaching files to a form. It combines a drop zone (drag-and-drop) with a button that opens the native picker, lists the chosen files with name and size, validates type, size and count locally, and lets each file be removed.

The component **does not send** files: the app makes the request and reports each file's progress with `setFileStatus()`. The field shows progress, failure and the retry button in the same list — see [Sending](#sending-progress-failure-and-retry).

## Comportamento

- **Antes de escolher:** título, marcação de opcional e restrições (formatos, tamanho, quantidade) ficam visíveis na área e associados a ela via `aria-describedby`. Com `required`, um texto oculto “Required.” também é lido.
- **Soltar não é o único caminho:** a área inteira é um `<button>` — Tab chega nela, Enter/Espaço e toque abrem o seletor.
- **Acumula ou substitui:** com `multiple`, cada nova seleção **soma** aos arquivos já presentes; sem `multiple`, um arquivo válido **substitui** o atual.
- **Duplicatas:** um arquivo idêntico a um da lista (nome, tamanho, tipo e data de modificação) é ignorado e anunciado como “already in the list”.
- **Seletor cancelado:** fechar o seletor do sistema sem escolher nada não altera a lista.
- **Arquivo inválido não derruba os válidos:** cada arquivo é validado sozinho. Os recusados aparecem na lista com borda de erro e uma mensagem que diz **qual arquivo**, **o problema** e **como resolver** — e não entram no `FormData` nem em `files`. Eles saem com o botão Remover ou na próxima seleção.
- **Nomes longos** quebram linha em qualquer ponto em vez de serem truncados, para continuarem identificáveis em telas pequenas e com zoom.

</Lang>

<Lang lang="en-US">
## Behaviour

- **Before choosing:** title, optional marker and constraints (formats, size, count) are visible in the zone and tied to it through `aria-describedby`. With `required`, a hidden “Required.” note is read too.
- **Dropping is not the only way:** the whole zone is a `<button>` — Tab reaches it, Enter/Space and touch open the picker.
- **Accumulate or replace:** with `multiple`, each new selection is **added** to the files already there; without `multiple`, a valid file **replaces** the current one.
- **Duplicates:** a file identical to one in the list (name, size, type and last-modified date) is skipped and announced as “already in the list”.
- **Cancelled picker:** closing the system picker without choosing leaves the list unchanged.
- **An invalid file does not drop the valid ones:** each file is validated on its own. Rejected files appear in the list with an error border and a message that names **the file**, **the problem** and **how to fix it** — and they are not in `FormData` or `files`. They leave with their Remove button or on the next selection.
- **Long names** wrap at any point instead of being truncated, so they stay identifiable on small screens and under zoom.

</Lang>

## Tipos restritos

## Restricted accept

`accept` filters the system picker and is re-checked when a file is dropped or picked. It **does not replace server-side validation**: type (by content, not just extension), size, count and content must be checked again on the backend — the browser accepts whatever the user renames.

## Teclado e leitor de tela

| Tecla           | Ação                                                                                  |
| --------------- | ------------------------------------------------------------------------------------- |
| Tab / Shift+Tab | Percorre a área e o botão Remover de **cada** arquivo.                                |
| Enter / Espaço  | Na área, abre o seletor. Em Remover, remove o arquivo; em Retry, pede nova tentativa. |

- Cada botão Remover e Retry tem o nome do arquivo no nome acessível (“Remove comprovante.pdf”, “Retry comprovante.pdf”).
- Depois de Retry, quando a aplicação volta o arquivo para `uploading` o botão some e o foco vai para o Remover do mesmo arquivo.
- Depois de remover, o foco vai para o botão Remover do arquivo que tomou o lugar, senão o anterior, senão a área — nunca para um elemento que sumiu.
- A lista é um `<ul>` rotulado; cada item expõe nome, tamanho e, se recusado, a mensagem de erro.
- Adições, recusas, remoções e mudanças de status (início, envio concluído, falha) são anunciadas numa região `role="status"` educada, sem mover o foco. Os passos do progresso **não** são anunciados — a barra (`role="progressbar"`, com o nome do arquivo) pode ser consultada a qualquer momento.
- Um arquivo enviado é desenhado como um selecionado, como no protótipo; o estado “uploaded” vai em texto oculto no item.

</Lang>

<Lang lang="en-US">
## Keyboard and screen reader

| Key             | Action                                                                                       |
| --------------- | -------------------------------------------------------------------------------------------- |
| Tab / Shift+Tab | Moves through the zone and the Remove button of **each** file.                               |
| Enter / Space   | On the zone, opens the picker. On Remove, removes the file; on Retry, asks to send it again. |

- Each Remove and Retry button carries the file name in its accessible name (“Remove receipt.pdf”, “Retry receipt.pdf”).
- After Retry, when the app sets the file back to `uploading` the button goes away and focus moves to the same file's Remove.
- After a removal, focus goes to the Remove button of the file that took its place, else the previous one, else the zone — never to an element that is gone.
- The list is a labelled `<ul>`; each item exposes name, size and, if rejected, the error message.
- Additions, rejections, removals and status changes (start, sent, failed) are announced in a polite `role="status"` region, without moving focus. Progress ticks are **not** announced — the bar (`role="progressbar"`, named after the file) can be checked at any time.
- A sent file is drawn like a selected one, as in the prototype; the “uploaded” state goes in hidden text on the item.

</Lang>

## Envio: progresso, falha e nova tentativa

A aplicação envia; o campo mostra. Ela pega os arquivos em `files` (ou em `lui-change`), faz a requisição e chama `setFileStatus()` a cada mudança. O item exibe uma barra de progresso enquanto `uploading`, borda de erro, mensagem e um botão **Retry** em `error`, e volta ao visual normal em `complete`.

</Lang>

<Lang lang="en-US">
## Sending: progress, failure and retry

The app sends; the field shows it. It takes the files from `files` (or from `lui-change`), makes the request and calls `setFileStatus()` on every change. The item shows a progress bar while `uploading`, an error border, a message and a **Retry** button on `error`, and goes back to its plain look on `complete`.

</Lang>

<Canvas of={FileUploadStories.UploadStates} />

```js
const field = document.querySelector('lui-file-upload');

async function upload(file) {
  field.setFileStatus(file, 'uploading', { progress: 0 });
  try {
    await send(file, (progress) =>
      field.setFileStatus(file, 'uploading', { progress })
    );
    field.setFileStatus(file, 'complete');
  } catch {
    field.setFileStatus(file, 'error', {
      message: 'Failed. Check your connection and retry.',
    });
  }
}

field.addEventListener('lui-retry', (e) => upload(e.detail.file));
```

<Lang lang="pt-BR">
Regras:

- **Defina quando o envio acontece.** No exemplo abaixo os arquivos vão pelo botão **Send**, para a pessoa revisar a lista antes. Se o produto enviar ao escolher, diga isso no `description`.
- **A mensagem de falha diz o que fazer** (“Check your connection and retry”), não só “Failed”.
- **Remover durante o envio cancela.** O arquivo sai de `files` e vem em `removed` no `lui-change`; aborte a requisição dele (`AbortController`).
- **`accept`, `max-size` e `max-files` não substituem a validação no servidor.** Revalide tipo pelo conteúdo, tamanho, quantidade e conteúdo no backend.
- **Não prometa** retomar envio interrompido nem manter arquivos depois de recarregar a página, a menos que o backend realmente suporte isso.

O exemplo simula a rede; arquivos com “fail” no nome falham na metade.

</Lang>

<Lang lang="en-US">
Rules:

- **Decide when sending happens.** In the example below files go with the **Send** button, so the person reviews the list first. If the product sends on selection, say so in `description`.
- **The failure message says what to do** (“Check your connection and retry”), not just “Failed”.
- **Removing during a send cancels it.** The file leaves `files` and comes in `removed` on `lui-change`; abort its request (`AbortController`).
- **`accept`, `max-size` and `max-files` do not replace server-side validation.** Re-check type by content, size, count and content on the backend.
- **Do not promise** resuming an interrupted upload or keeping files after a reload unless the backend really supports it.

The example simulates the network; files with “fail” in the name fail halfway.

</Lang>
