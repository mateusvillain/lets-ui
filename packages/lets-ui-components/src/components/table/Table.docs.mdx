# Table

Apresenta dados em linhas e colunas. O componente usa o `<table>` nativo, então a leitura por tecnologia assistiva vem da própria marcação: `<thead>`, `<tbody>` e `<th scope>`.

## Alinhamento à direita

Colunas de ações ou de valores podem ficar alinhadas ao fim. Coloque `.table__cell--end` no cabeçalho **e em cada célula** da coluna, para que título e conteúdo andem juntos. Use quando fizer sentido: ações e valores numéricos, que se comparam pelo fim. Texto corrido continua à esquerda.

<Canvas of={TableStories.Bordered} />

```html
<th scope="col" class="table__cell--end">Ações</th>
…
<td class="table__cell--end">
  <lui-icon-button aria-label="Ações de Ana Souza">…</lui-icon-button>
</td>
```

A classe usa `text-align: end`, então acompanha a direção de escrita (em idiomas da direita para a esquerda, o fim é a esquerda).

## Coluna só do tamanho do conteúdo

Por padrão as colunas dividem a largura da tabela. Colunas que não precisam de espaço, como ações, ids, tags de status ou uma caixa de seleção, ficam com `.table__cell--fit`: ela ocupa só a largura do conteúdo mais largo e as demais colunas dividem o resto. Como a medida vem do conteúdo, não há número para atualizar quando o texto muda.

Coloque a classe no cabeçalho **e em cada célula** da coluna: ela também impede a quebra de linha, então o conteúdo não pode ser longo. Combina com `.table__cell--end`.

<Canvas of={TableStories.Bordered} />

```html
<th scope="col" class="table__cell--fit table__cell--end">Ações</th>
…
<td class="table__cell--fit table__cell--end">
  <lui-icon-button aria-label="Ações de Ana Souza">…</lui-icon-button>
</td>
```

Fica de fora dessa classe qualquer coluna de texto corrido, que precisa quebrar linha.

## Header fixo

`sticky-header` mantém o cabeçalho visível enquanto as linhas rolam por baixo dele. Ele só tem efeito com `max-height`, que limita a altura da área: sem isso a tabela não rola na vertical e não há o que prender. Um número vale como pixels (`280`); qualquer medida CSS também serve (`20rem`).

<Canvas of={TableStories.StickyHeader} />

```html
<lui-table sticky-header max-height="280">
  <table>
    …
  </table>
</lui-table>
```

- A área vira uma região rolável, com `role="region"`, `tabindex="0"` e nome, para que o teclado também role na vertical.
- Ao navegar por teclado, a linha focada não fica escondida atrás do cabeçalho: o componente reserva a altura dele com `scroll-padding-top`.
- O cabeçalho usa o fundo `surface` neutro, opaco, para as linhas não aparecerem através dele. Se a tabela ficar sobre outra cor, ela aparece no cabeçalho.
- O `<caption>` rola junto com as linhas; só o cabeçalho fica.
- Em CSS puro, use `.table--sticky-header` na tabela e defina o `max-height` no `.table-wrapper`.

## Estrutura

A tabela fica dentro de `<lui-table>`, na marcação de quem usa. O Web Component não gera linhas nem células: ele coloca a classe `.table` na tabela, cuida da rolagem horizontal e da borda.

- A tabela precisa de um nome acessível. Veja [Nome da tabela](#nome-da-tabela).
- `<th scope="col">` no cabeçalho de cada coluna.
- `<th scope="row">` na primeira célula de cada linha, quando ela identifica a linha. Dados comuns ficam em `<td>`.
- Ações dentro das células precisam de nome próprio que diga a qual linha pertencem ("Ações de Ana Souza").

## Nome da tabela

Toda tabela de dados precisa de um nome acessível, para que o leitor de tela anuncie "tabela, Pedidos" e não apenas "tabela". O `<caption>` é opcional, e o Let's UI o estiliza como no design: título à esquerda, dentro da borda, acima do cabeçalho. A regra:

- **Com título visível (como no design):** use `<caption>`. Ele é o título e também o nome acessível.
- **Sem título visível:** use `aria-label` no `<table>`.
- **Título já existente fora da tabela** (um heading, por exemplo): use `aria-labelledby` no `<table>` apontando para ele.
- **Não use `aria-label` e `<caption>` juntos:** o `aria-label` prevalece e o caption passa a ser redundante.

<Canvas of={TableStories.WithoutCaption} />

## Rolagem horizontal

Quando a tabela é mais larga que o espaço disponível, a área vira uma região rolável. Ela ganha `role="region"`, `tabindex="0"` e um nome, para que o teclado consiga rolar. O nome vem de `label` ou, sem ele, do nome da própria tabela, na ordem do navegador: `aria-labelledby`, `aria-label` e `<caption>`. Um `aria-label` vazio conta como ausente. O componente acompanha mudanças nesses atributos e no texto do caption.

## Uso

### Web Component

```html
<lui-table bordered>
  <table>
    <caption>
      Pedidos
    </caption>
    <thead>
      <tr>
        <th scope="col">Nome</th>
        <th scope="col">Status</th>
      </tr>
    </thead>
    <tbody>
      <tr>
        <th scope="row">Ana Souza</th>
        <td>Concluído</td>
      </tr>
    </tbody>
  </table>
</lui-table>
```

### Classe CSS

<Canvas of={TableStories.CSSClass} />

```html
<div class="table-wrapper table-wrapper--bordered">
  <table class="table">
    <caption>
      Pedidos
    </caption>
    …
  </table>
</div>
```

Sem o Web Component, a região rolável é responsabilidade de quem usa: adicione `role="region"`, `tabindex="0"` e `aria-label` ao `.table-wrapper` se a tabela puder transbordar.

## Propriedades

| Propriedade    | Atributo        | Tipo      | Padrão  | Descrição                                                  |
| -------------- | --------------- | --------- | ------- | ---------------------------------------------------------- |
| `bordered`     | `bordered`      | `boolean` | `false` | Borda externa com cantos arredondados.                     |
| `label`        | `label`         | `string`  | `''`    | Nome da região rolável. Sem ele, usa o nome da tabela.     |
| `stickyHeader` | `sticky-header` | `boolean` | `false` | Mantém o cabeçalho visível na rolagem. Exige `max-height`. |
| `maxHeight`    | `max-height`    | `string`  | `''`    | Altura máxima da área; acima dela, rola na vertical.       |

## Acessibilidade

- A semântica é a do `<table>` nativo: nenhum `role` é sobrescrito.
- Dê sempre um nome à tabela: `aria-label`, `aria-labelledby` ou `<caption>`.
- Os estilos olham só as células da própria tabela: uma tabela dentro de uma célula não herda padding, divisores nem o header fixo.
- Com `<tfoot>` ou vários `<tbody>`, só a última linha da tabela fica sem divisor.
- O hover da linha é só um apoio visual; não carrega informação.
- Status dentro das células deve ter texto, não só cor.
