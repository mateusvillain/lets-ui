## Alinhamento à direita

Colunas de ações ou de valores podem ficar alinhadas ao fim. Coloque `.table__cell--end` no cabeçalho e em cada célula da coluna, para o título acompanhar o conteúdo. Ela serve para ações e valores numéricos. Texto corrido fica à esquerda.

## Right alignment

Action or value columns can be aligned to the end. Put `.table__cell--end` in the header and in every cell of the column, so the title follows the content. It is meant for actions and numeric values. Running text stays on the left.

A classe usa `text-align: end`, então segue a direção de escrita. Em idiomas escritos da direita para a esquerda, o fim é o lado esquerdo.

<Lang lang="pt-BR">
## Coluna só do tamanho do conteúdo

Por padrão as colunas dividem a largura da tabela. Uma coluna que não precisa de espaço, como ações, ids, tags de status ou caixa de seleção, pode usar `.table__cell--fit`. Ela fica com a largura do conteúdo mais largo, e as outras colunas dividem o resto. Como a medida vem do conteúdo, não há valor para atualizar quando o texto muda.

Coloque a classe no cabeçalho e em cada célula da coluna. Ela também impede a quebra de linha, então o conteúdo precisa ser curto. Pode ser usada junto com `.table__cell--end`.

</Lang>

<Lang lang="en-US">
## Content-sized column

By default the columns share the table width. A column that does not need space, such as actions, ids, status tags or a checkbox, can use `.table__cell--fit`. It takes the width of the widest content, and the other columns share the rest. Since the measurement comes from the content, there is no value to update when the text changes.

Put the class in the header and in every cell of the column. It also prevents line breaks, so the content must be short. It can be used together with `.table__cell--end`.

</Lang>

<Canvas of={TableStories.Bordered} />

<Lang lang="pt-BR">
```html

…
<td class="table__cell--fit table__cell--end">
  <lui-icon-button aria-label="Ações de Ana Souza">…</lui-icon-button>
</td>
```

Não use a classe em colunas de texto corrido, que precisam quebrar linha.

</Lang>

## Colunas ordenáveis

Para uma coluna ser ordenável, ponha um `<button class="table__sort">` dentro do `<th>`. O botão dá acesso por teclado e o nome da coluna. O `lui-table` cuida do resto: troca o `aria-sort` do `<th>`, mostra a seta e emite `lui-sort`.

</Lang>

<Lang lang="en-US">
## Sortable columns

For a column to be sortable, put a `<button class="table__sort">` inside the `<th>`. The button gives keyboard access and the column name. `lui-table` takes care of the rest: it swaps the `aria-sort` of the `<th>`, shows the arrow and emits `lui-sort`.

</Lang>

<Canvas of={TableStories.Sortable} />

<Lang lang="pt-BR">
```html
<lui-table>
  <table aria-label="Equipe">
    <thead>
      <tr>
        <th scope="col" data-column="name">
          <button type="button" class="table__sort">Nome</button>
        </th>
        <th scope="col">Função</th>
      </tr>
    </thead>
    …
  </table>
</lui-table>
```

```js
table.addEventListener('lui-sort', ({ detail }) => {
  // detail.column: o data-column do <th>, ou o texto do botão
  // detail.direction: 'ascending', 'descending' ou 'none'
});
```

- Cada clique avança a coluna: crescente, decrescente e sem ordem. Com `none`, o autor pode voltar à ordem original.
- Só uma coluna fica ordenada por vez. Ao ordenar uma, as outras voltam para `none`.
- O componente **não reordena as linhas**. Quem usa decide como: no navegador, como na story, ou pedindo os dados ao servidor.
- O `aria-sort` é colocado como `none` em todo `<th>` que tem o botão, se o autor não tiver definido um valor. Um `aria-sort` já escrito é mantido, então dá para abrir a tabela já ordenada.
- A seta vem do `aria-sort`: as duas setas esmaecidas sem ordem, e uma seta na cor do título quando a coluna está ordenada.
- Em CSS puro, `.table__sort` já tem o visual, mas o `aria-sort` e o evento ficam por sua conta.

</Lang>

<Lang lang="en-US">
```html
<lui-table>
  <table aria-label="Team">
    <thead>
      <tr>
        <th scope="col" data-column="name">
          <button type="button" class="table__sort">Name</button>
        </th>
        <th scope="col">Role</th>
      </tr>
    </thead>
    …
  </table>
</lui-table>
```

```js
table.addEventListener('lui-sort', ({ detail }) => {
  // detail.column: the data-column of the <th>, or the button text
  // detail.direction: 'ascending', 'descending' or 'none'
});
```

- Each click advances the column: ascending, descending and no order. With `none`, the author can return to the original order.
- Only one column is sorted at a time. When one is sorted, the others go back to `none`.
- The component **does not reorder the rows**. The consumer decides how: in the browser, as in the story, or by requesting the data from the server.
- `aria-sort` is set to `none` on every `<th>` that has the button, if the author has not set a value. An `aria-sort` already written is kept, so it is possible to open the table already sorted.
- The arrow comes from `aria-sort`: the two faded arrows when there is no order, and one arrow in the title color when the column is sorted.
- In plain CSS, `.table__sort` already has the look, but `aria-sort` and the event are up to you.

</Lang>

<Lang lang="pt-BR">
## Header fixo

`sticky-header` mantém o cabeçalho visível enquanto as linhas rolam. Ele só funciona com `max-height`, que limita a altura da área. Sem altura limitada a tabela não rola na vertical. Um número vale como pixels (`280`), e qualquer medida CSS também serve (`20rem`).

</Lang>

<Lang lang="en-US">
## Sticky header

`sticky-header` keeps the header visible while the rows scroll. It only works with `max-height`, which limits the height of the area. Without a limited height the table does not scroll vertically. A number counts as pixels (`280`), and any CSS measurement also works (`20rem`).

</Lang>

<Canvas of={TableStories.StickyHeader} />

<Lang lang="pt-BR">
```html
<lui-table sticky-header max-height="280">
  <table>
    …
  </table>
</lui-table>
```

- A área vira uma região com `role="region"`, `tabindex="0"` e nome, para o teclado conseguir rolar na vertical.
- Ao navegar por teclado, a linha com foco não fica atrás do cabeçalho. O componente define `scroll-padding-top` com a altura dele.
- O cabeçalho usa o fundo `surface` neutro e opaco, para as linhas não aparecerem por trás. Em uma página com outra cor de fundo, o cabeçalho vai destoar.
- O `<caption>` rola junto com as linhas; só o cabeçalho fica.
- Em CSS puro, use `.table--sticky-header` na tabela e defina o `max-height` no `.table-wrapper`.

</Lang>

<Lang lang="en-US">
```html
<lui-table sticky-header max-height="280">
  <table>
    …
  </table>
</lui-table>
```

- The area becomes a region with `role="region"`, `tabindex="0"` and a name, so the keyboard can scroll vertically.
- When navigating by keyboard, the focused row does not end up behind the header. The component sets `scroll-padding-top` with its height.
- The header uses the neutral, opaque `surface` background, so the rows do not show through. On a page with another background color, the header will stand out.
- The `<caption>` scrolls with the rows; only the header stays.
- In plain CSS, use `.table--sticky-header` on the table and set `max-height` on `.table-wrapper`.

</Lang>

## Estrutura

Você escreve o `<table>` dentro de `<lui-table>`. O Web Component não cria linhas nem células. Ele só coloca a classe `.table` na tabela e cuida da borda e da rolagem.

- A tabela precisa de um nome acessível. Veja [Nome da tabela](#nome-da-tabela).
- `<th scope="col">` no cabeçalho de cada coluna.
- `<th scope="row">` na primeira célula de cada linha, quando ela identifica a linha. Dados comuns ficam em `<td>`.
- Ações dentro das células precisam de nome próprio que diga a qual linha pertencem ("Ações de Ana Souza").

</Lang>

<Lang lang="en-US">
## Structure

You write the `<table>` inside `<lui-table>`. The Web Component does not create rows or cells. It only puts the `.table` class on the table and takes care of the border and the scrolling.

- The table needs an accessible name. See [Table name](#table-name).
- `<th scope="col">` in the header of each column.
- `<th scope="row">` in the first cell of each row, when it identifies the row. Regular data goes in `<td>`.
- Actions inside the cells need their own name that says which row they belong to ("Actions for Ana Souza").

</Lang>

<Lang lang="pt-BR">
## Nome da tabela

Toda tabela de dados precisa de um nome, para o leitor de tela anunciar "tabela, Pedidos" e não só "tabela". O `<caption>` é opcional. Quando usado, ele aparece como no design: título à esquerda, dentro da borda, acima do cabeçalho. Como nomear:

- Com título visível, como no design: use `<caption>`. Ele é o título e também o nome.
- Sem título visível: use `aria-label` no `<table>`.
- Com um título em outro lugar da página, como um heading: use `aria-labelledby` no `<table>`, apontando para ele.
- Não use `aria-label` e `<caption>` juntos. O `aria-label` vale e o caption fica repetido.

</Lang>

<Lang lang="en-US">
## Table name

Every data table needs a name, so the screen reader announces "table, Orders" and not just "table". The `<caption>` is optional. When used, it appears as in the design: title on the left, inside the border, above the header. How to name it:

- With a visible title, as in the design: use `<caption>`. It is the title and also the name.
- Without a visible title: use `aria-label` on the `<table>`.
- With a title elsewhere on the page, such as a heading: use `aria-labelledby` on the `<table>`, pointing to it.
- Do not use `aria-label` and `<caption>` together. `aria-label` wins and the caption becomes duplicated.

</Lang>

<Lang lang="pt-BR">
## Rolagem horizontal

Quando a tabela é mais larga que o espaço disponível, a área ganha `role="region"`, `tabindex="0"` e um nome, para o teclado conseguir rolar. O nome vem de `label` ou, sem ele, do nome da própria tabela, na ordem `aria-labelledby`, `aria-label` e `<caption>`. Um `aria-label` vazio é ignorado. Se esses atributos ou o texto do caption mudarem, o nome acompanha.

</Lang>

<Lang lang="en-US">
## Horizontal scrolling

When the table is wider than the available space, the area receives `role="region"`, `tabindex="0"` and a name, so the keyboard can scroll. The name comes from `label` or, without it, from the name of the table itself, in the order `aria-labelledby`, `aria-label` and `<caption>`. An empty `aria-label` is ignored. If those attributes or the caption text change, the name follows.

</Lang>

## Acessibilidade

- A semântica é a do `<table>` nativo. Nenhum `role` é sobrescrito.
- Dê sempre um nome à tabela, com `aria-label`, `aria-labelledby` ou `<caption>`.
- Em colunas ordenáveis, o botão dá o nome e o foco, e o `aria-sort` do `<th>` informa o estado, no padrão do WAI-ARIA Authoring Practices. O leitor de tela lê a direção ao chegar no cabeçalho, mas o componente não faz um anúncio extra ao clicar.
- Os estilos valem só para as células da própria tabela. Uma tabela dentro de uma célula não recebe padding, divisores nem header fixo.
- Com `<tfoot>` ou vários `<tbody>`, só a última linha da tabela fica sem divisor.
- O hover da linha só ajuda a enxergar a linha. Nenhuma informação depende dele.
- Status dentro das células deve ter texto, não só cor.

</Lang>

<Lang lang="en-US">
## Accessibility

- The semantics are those of the native `<table>`. No `role` is overridden.
- Always give the table a name, with `aria-label`, `aria-labelledby` or `<caption>`.
- In sortable columns, the button provides the name and the focus, and the `aria-sort` of the `<th>` reports the state, following the WAI-ARIA Authoring Practices pattern. The screen reader reads the direction when reaching the header, but the component does not make an extra announcement on click.
- The styles apply only to the cells of the table itself. A table inside a cell does not receive padding, dividers or a sticky header.
- With `<tfoot>` or multiple `<tbody>`, only the last row of the table has no divider.
- The row hover only helps to see the row. No information depends on it.
- Status inside the cells must have text, not only color.

</Lang>
