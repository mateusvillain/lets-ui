# OTP Input

Field for one-time codes (OTP) and verification codes. Renders one box per character: while typing, focus moves to the next one; `Backspace` in an empty box goes back to the previous one and clears it; pasting a code distributes it across the boxes.

## Separador

O separador é opcional: sem `separator`, as caixas ficam numa linha só. O atributo recebe a posição da caixa após a qual o separador aparece — `separator="3"` divide seis caixas em 3 + 3. Para mais de um separador, liste as posições separadas por vírgula (`separator="2,4"`). Posições fora do intervalo entre a primeira e a última caixa são ignoradas.

</Lang>

<Lang lang="en-US">
## Separator

The separator is optional: without `separator`, the boxes stay in a single row. The attribute receives the position of the box after which the separator appears — `separator="3"` splits six boxes into 3 + 3. For more than one separator, list the positions separated by commas (`separator="2,4"`). Positions outside the range between the first and the last box are ignored.

</Lang>

<Lang lang="pt-BR">
## Colar e preencher automaticamente

Colar um código completo preenche todas as caixas a partir da primeira, qualquer que seja a caixa em foco. Um trecho menor é colado a partir da caixa em foco. Caracteres que o `type` não aceita são descartados.

A primeira caixa tem `autocomplete="one-time-code"`, então o código recebido por SMS pode ser sugerido pelo sistema e é distribuído da mesma forma.

</Lang>

<Lang lang="en-US">
## Pasting and autofill

Pasting a complete code fills all boxes starting from the first one, whatever box is focused. A shorter snippet is pasted starting from the focused box. Characters the `type` does not accept are discarded.

The first box has `autocomplete="one-time-code"`, so the code received by SMS can be suggested by the system and is distributed the same way.

</Lang>

<Lang lang="pt-BR">
## Integração com formulários

O `lui-otp-input` é um form-associated custom element: o código é enviado no `FormData` sob o atributo `name`. Com `required`, o formulário não é submetido enquanto o campo estiver vazio; um código incompleto também é inválido.

</Lang>

<Lang lang="en-US">
## Form integration

`lui-otp-input` is a form-associated custom element: the code is submitted in the `FormData` under the `name` attribute. With `required`, the form is not submitted while the field is empty; an incomplete code is also invalid.

## Acessibilidade

- As caixas ficam num elemento com `role="group"` nomeado por `label`: por `aria-label` quando o rótulo está oculto, e por `aria-labelledby` apontando para o rótulo visível com `show-label`.
- Cada caixa é um `<input>` nativo com `aria-label` indicando sua posição ("Character 2 of 6").
- O separador é decorativo (`aria-hidden="true"`).
- Com `error`, as caixas recebem `aria-invalid="true"`, e a mensagem de erro ou de ajuda fica ligada a elas por `aria-describedby`.
- O campo é uma única parada de `Tab`: ao entrar, o foco vai para a primeira caixa vazia (ou para a última, com o código completo), e `Tab` ou `Shift+Tab` a partir de qualquer caixa saem do campo.
- Setas, `Home` e `End` movem o foco entre as caixas; em `dir="rtl"`, as setas seguem a direção de leitura. `Delete` limpa a caixa sem mover o foco. Ao receber o foco, o conteúdo da caixa é selecionado, então a próxima tecla o substitui.
- `Enter` envia o formulário associado.
- Colar nunca é bloqueado, e a primeira caixa tem `autocomplete="one-time-code"`, para que o sistema ou um gerenciador de senhas preencha o código. Assim ninguém precisa transcrever o código à mão (WCAG 3.3.8, Autenticação Acessível).
- O código aparece em texto claro, sem máscara.
- `focus()` no elemento leva o foco à primeira caixa vazia.

### Responsabilidades de quem usa

- Com o rótulo oculto, garanta que a tela explique o campo em texto visível, por exemplo num título, ou use `show-label`. Informe também o tamanho e o formato do código, por exemplo com `hint="Digite o código de 6 dígitos enviado por SMS."`.
- Se o formulário for enviado automaticamente em `lui-complete`, mantenha também um botão de envio.
- Depois de uma validação que falhou, não limpe o código: a pessoa pode corrigir só o caractere errado.

</Lang>

<Lang lang="en-US">
## Accessibility

- The boxes sit in an element with `role="group"` named by `label`: through `aria-label` when the label is hidden, and through `aria-labelledby` pointing to the visible label with `show-label`.
- Each box is a native `<input>` with `aria-label` indicating its position ("Character 2 of 6").
- The separator is decorative (`aria-hidden="true"`).
- With `error`, the boxes receive `aria-invalid="true"`, and the error or help message is linked to them through `aria-describedby`.
- The field is a single `Tab` stop: on entering, focus goes to the first empty box (or to the last one, with the complete code), and `Tab` or `Shift+Tab` from any box leaves the field.
- Arrows, `Home` and `End` move focus between the boxes; in `dir="rtl"`, the arrows follow the reading direction. `Delete` clears the box without moving focus. On receiving focus, the box content is selected, so the next key replaces it.
- `Enter` submits the associated form.
- Pasting is never blocked, and the first box has `autocomplete="one-time-code"`, so the system or a password manager fills in the code. That way nobody has to transcribe the code by hand (WCAG 3.3.8, Accessible Authentication).
- The code appears in clear text, without a mask.
- `focus()` on the element moves focus to the first empty box.

### Consumer responsibilities

- With the label hidden, make sure the screen explains the field in visible text, for example in a title, or use `show-label`. Also state the size and format of the code, for example with `hint="Enter the 6-digit code sent by SMS."`.
- If the form is submitted automatically on `lui-complete`, also keep a submit button.
- After a validation that failed, do not clear the code: the person can fix only the wrong character.

</Lang>

## Uso

### Web Component

```html
<lui-otp-input type="number" name="code" required></lui-otp-input>

<script>
  document
    .querySelector('lui-otp-input')
    .addEventListener('lui-complete', (event) => {
      console.log(event.detail.value);
    });
</script>
```

### Classe CSS

```html
<div class="otp-input">
  <!-- Opcional: sem rótulo visível, use aria-label no grupo -->
  <span class="otp-input__label" id="otp-label">Verification code</span>
  <div class="otp-input__group" role="group" aria-labelledby="otp-label">
    <input
      class="otp-input__field"
      type="text"
      inputmode="numeric"
      autocomplete="one-time-code"
      aria-label="Character 1 of 6"
    />
    <input
      class="otp-input__field"
      type="text"
      inputmode="numeric"
      aria-label="Character 2 of 6"
    />
    <input
      class="otp-input__field"
      type="text"
      inputmode="numeric"
      aria-label="Character 3 of 6"
    />
    <span class="otp-input__separator" aria-hidden="true"></span>
    <input
      class="otp-input__field"
      type="text"
      inputmode="numeric"
      aria-label="Character 4 of 6"
    />
```
