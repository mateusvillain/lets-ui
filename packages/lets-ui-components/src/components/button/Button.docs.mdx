# Button

Dispara uma ação: salvar um formulário, confirmar uma exclusão, abrir um diálogo. Mostra um texto que nomeia a ação e, opcionalmente, ícones antes ou depois dele. Com `href`, a mesma aparência vale para um link.

# Button

Triggers an action: save a form, confirm a deletion, open a dialog. Shows a text that names the action and, optionally, icons before or after it. With `href`, the same appearance is used for a link.

<Lang lang="pt-BR">
## Quando usar

Use o Button para ações que acontecem na página atual ou que enviam dados: salvar, enviar, excluir, abrir um Modal ou um Drawer.

- Para levar a outra página com a aparência de um botão, como um CTA "Ver curso", use o próprio Button com `href` (veja [Como link](#como-link-href)). Ele renderiza um `<a>`.
- Para um link dentro de um texto ou numa lista de navegação, use o [componente Link](?path=/docs/navigation-link--docs).
- Quando não há espaço para texto e o ícone basta para reconhecer a ação, use o [Icon Button](?path=/docs/actionable-icon-button--docs). Para fechar um painel, use o [Close Button](?path=/docs/actionable-close-button--docs).
- Para um conjunto de ações a partir de um único botão, use o [Dropdown Menu](?path=/docs/actionable-dropdown-menu--docs) com um Button como gatilho.
</Lang>

<Lang lang="en-US">
## When to use

Use Button for actions that happen on the current page or that submit data: save, submit, delete, open a Modal or a Drawer.

- To go to another page with the appearance of a button, such as a "View course" CTA, use Button itself with `href` (see [As a link](#as-a-link-href)). It renders an `<a>`.
- For a link inside a text or in a navigation list, use the [Link component](?path=/docs/navigation-link--docs).
- When there is no room for text and the icon alone is enough to recognize the action, use [Icon Button](?path=/docs/actionable-icon-button--docs). To close a panel, use [Close Button](?path=/docs/actionable-close-button--docs).
- For a set of actions from a single button, use [Dropdown Menu](?path=/docs/actionable-dropdown-menu--docs) with a Button as the trigger.
</Lang>

## Texto do botão

O texto vem do atributo `label` ou do conteúdo do slot padrão. Quando os dois existem, o conteúdo do slot é o que aparece. Esse texto também é o nome acessível do botão.

Use `aria-label` só quando o texto visível não basta para descrever a ação. Nesse caso, comece o `aria-label` pelo texto visível ("Excluir" → "Excluir arquivo"), para que quem usa comando de voz possa dizer o que vê (WCAG 2.5.3).
</Lang>

<Lang lang="en-US">
## Button text

The text comes from the `label` attribute or from the default slot content. When both exist, the slot content is what shows. That text is also the button's accessible name.

Use `aria-label` only when the visible text is not enough to describe the action. In that case, start the `aria-label` with the visible text ("Delete" → "Delete file"), so that people using voice commands can say what they see (WCAG 2.5.3).
</Lang>

## Disabled

`disabled` desabilita o botão: ele fica opaco, não responde a clique e sai da ordem de tabulação. Dentro de um `<fieldset disabled>`, o botão também fica desabilitado.

Como o botão desabilitado não recebe foco, quem navega por teclado ou leitor de tela não chega até ele. Dentro de um Tooltip, o foco vai para o wrapper do tooltip, que mostra o texto mas é anunciado como grupo, sem o papel de botão nem o estado indisponível. Se a pessoa precisa saber por que a ação está indisponível, explique o motivo num texto visível perto do botão.
</Lang>

<Lang lang="en-US">
## Disabled

`disabled` disables the button: it becomes opaque, does not respond to clicks and leaves the tab order. Inside a `<fieldset disabled>`, the button is also disabled.

Because a disabled button cannot receive focus, people navigating with a keyboard or screen reader never reach it. Inside a Tooltip, focus goes to the tooltip wrapper, which shows the text but is announced as a group, without the button role or the unavailable state. If people need to know why the action is unavailable, explain the reason in visible text near the button.
</Lang>

## Loading

`loading` mostra um spinner e bloqueia a ação enquanto uma operação está em andamento. O botão não fica opaco nem perde o foco: ele continua com a aparência ativa, para mostrar que algo está acontecendo, e recebe `aria-busy="true"` e `aria-disabled="true"`.

Os ícones `prefix` e `suffix` dão lugar ao spinner. O texto continua visível, seja ele passado por `label` ou pelo slot, e segue sendo o nome acessível do botão.
</Lang>

<Lang lang="en-US">
## Loading

`loading` shows a spinner and blocks the action while an operation is in progress. The button does not become opaque or lose focus: it keeps its active appearance, to show that something is happening, and receives `aria-busy="true"` and `aria-disabled="true"`.

The `prefix` and `suffix` icons give way to the spinner. The text stays visible, whether it comes from `label` or from the slot, and remains the button's accessible name.

## Como link (`href`)

Quando o controle **navega ou baixa** um arquivo em vez de executar uma ação, ele é um link. Com `href`, o componente renderiza `<a>` no lugar de `<button>`, com a mesma aparência e os mesmos atributos de estilo (`variant`, `size`, `block`).

Assim o link mantém o que se perde ao navegar por JavaScript a partir de um botão: abrir em nova aba, menu do botão direito, clique do meio, Ctrl/Cmd + clique e `download`.
</Lang>

<Lang lang="en-US">
## As a link (`href`)

When the control **navigates or downloads** a file instead of running an action, it is a link. With `href`, the component renders `<a>` instead of `<button>`, with the same appearance and the same style attributes (`variant`, `size`, `block`).

That way the link keeps what is lost when navigating through JavaScript from a button: opening in a new tab, the right-click menu, middle click, Ctrl/Cmd + click and `download`.
</Lang>

<Lang lang="pt-BR">
### Desabilitado e loading

Links não têm `disabled` nativo. Com `disabled` ou `loading`, o `href` é omitido, então o elemento não navega por clique, clique do meio ou "abrir em nova aba". `aria-disabled="true"` e `role="link"` mantêm o anúncio correto em leitores de tela.

Os dois estados diferem no foco. `disabled` recebe `tabindex="-1"` e sai da ordem de tabulação, como um botão nativo desabilitado. `loading` é transitório e recebe `tabindex="0"`, para manter o foco de quem já estava no elemento quando a operação começou: sem `href`, uma âncora não é focável nem por código.
</Lang>

<Lang lang="en-US">
### Disabled and loading

Links have no native `disabled`. With `disabled` or `loading`, `href` is omitted, so the element does not navigate through clicks, middle click or "open in a new tab". `aria-disabled="true"` and `role="link"` keep the announcement correct in screen readers.

The two states differ in focus. `disabled` receives `tabindex="-1"` and leaves the tab order, like a native disabled button. `loading` is transient and receives `tabindex="0"`, to keep the focus of whoever was already on the element when the operation started: without `href`, an anchor is not focusable, not even by code.
</Lang>

## Estado de componentes acionados

Quando o botão abre ou alterna algo, como um menu, um painel ou um filtro, informe o estado com `aria-expanded`, `aria-haspopup` ou `aria-pressed` no próprio `<lui-button>`. O componente leva esses atributos ao controle interno, que é o que o leitor de tela anuncia, e os remove do elemento externo: lá eles criariam um segundo nó, sem papel, na árvore de acessibilidade. `aria-pressed` só se aplica sem `href`, já que links não têm estado pressionado.

Como o atributo sai do `<lui-button>`, seletores como `lui-button[aria-expanded="true"]` e `getAttribute('aria-expanded')` não o encontram. Leia a propriedade (`button.ariaExpanded`). Para limpar um estado, use um valor explícito (`aria-expanded="false"`) ou a propriedade com `null`: remover um atributo que o componente já consumiu não tem efeito.

Como `slot="trigger"` de um Modal, de um Drawer ou de um Dropdown Menu, o botão recebe esse estado do próprio componente e anuncia "recolhido" ou "expandido" sem configuração adicional. O `aria-controls` não é repassado: um ID não pode ser referenciado entre shadow roots diferentes.
</Lang>

<Lang lang="en-US">
## State of triggered components

When the button opens or toggles something, such as a menu, a panel or a filter, report the state with `aria-expanded`, `aria-haspopup` or `aria-pressed` on the `<lui-button>` itself. The component moves those attributes to the internal control, which is what the screen reader announces, and removes them from the outer element: there they would create a second, role-less node in the accessibility tree. `aria-pressed` only applies without `href`, since links have no pressed state.

Because the attribute leaves the `<lui-button>`, selectors such as `lui-button[aria-expanded="true"]` and `getAttribute('aria-expanded')` do not find it. Read the property (`button.ariaExpanded`) instead. To clear a state, use an explicit value (`aria-expanded="false"`) or the property with `null`: removing an attribute the component has already consumed has no effect.

As the `slot="trigger"` of a Modal, a Drawer or a Dropdown Menu, the button receives that state from the component itself and announces "collapsed" or "expanded" with no extra configuration. `aria-controls` is not forwarded: an ID cannot be referenced across different shadow roots.
</Lang>

## Com Tooltip

Dentro de um [Tooltip](?path=/docs/content-tooltip--docs), o texto do tooltip vira a descrição do botão (`aria-description`): o leitor de tela anuncia primeiro o nome do botão e depois o texto do tooltip. O botão continua sendo a única parada de tabulação, e o tooltip abre no foco e no hover.

Use o tooltip para informação complementar. Tudo que a pessoa precisa para entender a ação deve estar no texto do botão.
</Lang>

<Lang lang="en-US">
## With Tooltip

Inside a [Tooltip](?path=/docs/content-tooltip--docs), the tooltip text becomes the button description (`aria-description`): the screen reader announces the button name first and then the tooltip text. The button remains the only tab stop, and the tooltip opens on focus and hover.

Use the tooltip for complementary information. Everything a person needs to understand the action must be in the button text.
</Lang>

## Integração com formulários

`type="submit"` e `type="reset"` funcionam nativamente com o `<form>` pai. Dois botões de submit com `name` e `value` diferentes indicam, nos dados enviados, qual ação foi escolhida. O atributo `form` associa o botão a um formulário pelo ID, mesmo fora do elemento `<form>`.
</Lang>

<Lang lang="en-US">
## Form integration

`type="submit"` and `type="reset"` work natively with the parent `<form>`. Two submit buttons with different `name` and `value` indicate, in the submitted data, which action was chosen. The `form` attribute associates the button with a form by ID, even outside the `<form>` element.

## Autofocus

`autofocus` move o foco para o botão quando o contexto aparece. O caso mais comum é a ação principal de um diálogo: ao abrir, o foco já está no botão certo, e a pessoa confirma com Enter sem precisar navegar.

**Evite em páginas inteiras.** Receber o foco no meio do conteúdo desorienta quem usa leitor de tela ou teclado, que espera começar pelo topo da página. Reserve para contextos isolados e passageiros, como Modals, Drawers e confirmações.
</Lang>

<Lang lang="en-US">
## Autofocus

`autofocus` moves focus to the button when the context appears. The most common case is the main action of a dialog: on open, focus is already on the right button, and the person confirms with Enter without navigating.

**Avoid it on whole pages.** Receiving focus in the middle of the content disorients people using a screen reader or keyboard, who expect to start at the top of the page. Reserve it for isolated, transient contexts, such as Modals, Drawers and confirmations.
</Lang>

## Classe CSS (sem Web Component)

Sem o Web Component, use `<button class="btn btn--{variant} btn--{size}">` ou `<a class="btn ...">` para links. Também ficam a cargo de quem usa:

- o `type` do botão, que é `submit` por padrão dentro de um `<form>`;
- o spinner, o `aria-busy` e o bloqueio de clique do estado de loading;
- o `aria-disabled` e a remoção do `href` num link desabilitado;
- o `rel="noopener noreferrer"` com `target="_blank"`.
</Lang>

<Lang lang="en-US">
## CSS class (without Web Component)

Without the Web Component, use `<button class="btn btn--{variant} btn--{size}">` or `<a class="btn ...">` for links. These also become the responsibility of the consumer:

- the button `type`, which is `submit` by default inside a `<form>`;
- the spinner, the `aria-busy` and the click blocking of the loading state;
- the `aria-disabled` and the removal of `href` in a disabled link;
- the `rel="noopener noreferrer"` with `target="_blank"`.
</Lang>

| `aria-expanded` | `string`                                                         | —         | Open/closed state of what the button controls. Forwarded to the internal control. |
| `aria-haspopup` | `string`                                                         | —         | Type of popup the button opens. Forwarded to the internal control.             |
| `aria-pressed`  | `string`                                                         | —         | Toggle button state. Forwarded to the internal control, ignored with `href`.   |

### Slots

| Slot      | Description                                                       |
| --------- | ----------------------------------------------------------------- |
| (default) | Button text. Takes precedence over `label`.                       |
| `prefix`  | Icon before the text. Replaced by the spinner during `loading`.   |
| `suffix`  | Icon after the text. Disappears during `loading`.                 |
</Lang>
