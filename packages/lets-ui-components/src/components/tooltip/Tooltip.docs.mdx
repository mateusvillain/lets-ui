## Acessibilidade

### Trigger customizado

O trigger deve ser **um** controle focável: um `<button>`, `<a href>`, campo de formulário nativo,
`lui-button`, `lui-close-button`, `lui-icon-button` ou `lui-link`. Ele pode estar dentro de outro
elemento, como um `<span>`; o Tooltip usa o primeiro controle focável que encontrar no conteúdo, e
acompanha o conteúdo quando ele muda depois. Outros componentes do Let's UI, como `lui-input` ou
`lui-select`, ainda não são suportados como trigger.

- **Uma única parada de `Tab`**, no próprio controle. O Tooltip não adiciona nenhum elemento focável
  ao redor dele.
- **O texto do tooltip vira a descrição do controle.** O Tooltip define `aria-description` com o
  valor de `text` no trigger. Com `lui-button`, `lui-close-button`, `lui-icon-button` e `lui-link`, a descrição é
  repassada ao `<button>` ou `<a>` interno, que é quem o leitor de tela anuncia. O host não recebe o
  atributo, para não aparecer como um segundo nó na árvore de acessibilidade.
- **Um texto igual ao nome do trigger não vira descrição.** Quando `text` repete o nome do controle
  (`aria-labelledby`, `aria-label` ou, sem eles, o texto que ele renderiza, ignorando maiúsculas e
  diferenças de espaço), o
  Tooltip não define `aria-description`, e o leitor de tela anuncia o nome uma vez só. Se `text`
  ou o nome mudar depois, a descrição acompanha.
- O tooltip abre com o ponteiro sobre o trigger e com o foco de teclado nele.
- **Uma descrição própria do trigger** em `aria-description` é substituída pelo texto do tooltip
  enquanto ele estiver dentro do Tooltip, e restaurada quando sair. Se o texto repetir o nome, a
  descrição do autor é mantida. Já `aria-describedby` tem
  precedência sobre `aria-description`: um trigger que use os dois anuncia só o que o
  `aria-describedby` referencia. Nesse caso, inclua o texto do tooltip no elemento referenciado.

O Tooltip não usa `aria-describedby` no trigger customizado: o conteúdo fica no shadow root do
componente, e um ID não pode ser referenciado de fora dele. `aria-description` é um atributo do
ARIA 1.3 e leva o texto em si, sem referência.

Um `lui-icon-button` sem texto visível continua precisando de um `aria-label`: o tooltip descreve o
botão, mas não lhe dá um nome.

```html
<lui-tooltip text="Excluir o item">
  <lui-icon-button aria-label="Excluir">
    <svg aria-hidden="true">…</svg>
  </lui-icon-button>
</lui-tooltip>
```

### Trigger sem controle focável

Se o conteúdo não tiver nada focável, como um texto, ou se o controle estiver desabilitado, o
Tooltip torna o próprio contêiner do trigger focável e o descreve com o conteúdo do tooltip, para que
o texto continue acessível pelo teclado. É o caso de um tooltip que explica por que um botão está
desabilitado.
Prefira um controle real sempre que o tooltip explicar uma ação.

### Sem trigger

Sem conteúdo, o Tooltip renderiza um `<button>` próprio com o texto de `label`, descrito pelo
conteúdo do tooltip via `aria-describedby`.

## Accessibility

### Custom trigger

The trigger must be **one** focusable control: a `<button>`, `<a href>`, native form field,
`lui-button`, `lui-close-button`, `lui-icon-button` or `lui-link`. It may be inside another
element, such as a `<span>`; the Tooltip uses the first focusable control it finds in the content, and
follows the content when it changes later. Other Let's UI components, such as `lui-input` or
`lui-select`, are not yet supported as a trigger.

- **A single `Tab` stop**, on the control itself. The Tooltip does not add any focusable element
  around it.
- **The tooltip text becomes the control description.** The Tooltip sets `aria-description` with the
  value of `text` on the trigger. With `lui-button`, `lui-close-button`, `lui-icon-button` and `lui-link`, the description is
  forwarded to the internal `<button>` or `<a>`, which is what the screen reader announces. The host does not receive the
  attribute, so it does not appear as a second node in the accessibility tree.
- **A text equal to the trigger name does not become a description.** When `text` repeats the control name
  (`aria-labelledby`, `aria-label` or, without them, the text it renders, ignoring case and
  spacing differences), the
  Tooltip does not set `aria-description`, and the screen reader announces the name only once. If `text`
  or the name changes later, the description follows.
- The tooltip opens with the pointer over the trigger and with keyboard focus on it.
- **The trigger's own description** in `aria-description` is replaced by the tooltip text
  while it is inside the Tooltip, and restored when it leaves. If the text repeats the name, the
  author description is kept. `aria-describedby` takes
  precedence over `aria-description`: a trigger that uses both announces only what
  `aria-describedby` references. In that case, include the tooltip text in the referenced element.

The Tooltip does not use `aria-describedby` on the custom trigger: the content stays in the component
shadow root, and an ID cannot be referenced from outside it. `aria-description` is an ARIA 1.3
attribute and carries the text itself, without a reference.

A `lui-icon-button` without visible text still needs an `aria-label`: the tooltip describes the
button, but does not give it a name.

```html
<lui-tooltip text="Delete item">
  <lui-icon-button aria-label="Delete">
    <svg aria-hidden="true">…</svg>
  </lui-icon-button>
</lui-tooltip>
```

### Trigger without a focusable control

If the content has nothing focusable, such as a text, or if the control is disabled, the
Tooltip makes the trigger container itself focusable and describes it with the tooltip content, so
the text stays accessible by keyboard. This is the case of a tooltip that explains why a button is
disabled.
Prefer a real control whenever the tooltip explains an action.

### Without a trigger

Without content, the Tooltip renders its own `<button>` with the `label` text, described by the
tooltip content through `aria-describedby`.

## Uso

### Web Component

```html
<lui-tooltip
  text="Texto do tooltip"
  position="top"
  label="Hover aqui"
></lui-tooltip>
```

### Classe CSS

```html
<div class="tooltip tooltip--top">
  <button class="tooltip__trigger">Hover aqui</button>
  <div role="tooltip" class="tooltip__content">Texto do tooltip</div>
</div>
```
