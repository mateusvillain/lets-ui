## Write the keys

- Follow the **platform convention**: modifiers first (`Ctrl`, `Alt`, `Shift`, `Cmd`) and the main key last.
- Use the **names** printed on the keyboard: `Enter`, `Esc`, `Tab`.
- Show the shortcut for the **user's system**: `⌘` on macOS and `Ctrl` on Windows and Linux.

<DosDonts variant="do" title="Modifiers before the key">
  "Ctrl + K" or "⌘ K". It follows the convention and reads the way it is typed.
</DosDonts>

<DosDonts variant="dont" title="Reversed order or made-up names">
  "K + Control" or "Press the command button". It gets in the way of recognizing the shortcut.
</DosDonts>

## Where to show it

- At the end of a **menu** row, aligned to the right.
- Inside **tooltips** of buttons that have a shortcut.
- In a list of **commands** or in the product's help.

## Useful shortcuts

Show shortcuts only for **frequent** or very useful actions. Too many shortcuts become noise.

## Best practices

- Make sure the shortcut **actually works**, and that it does not conflict with the browser's and the system's.
- Always offer a way to perform the action without the shortcut.
- Avoid single-letter shortcuts without a modifier, which fire by mistake while typing in fields.
