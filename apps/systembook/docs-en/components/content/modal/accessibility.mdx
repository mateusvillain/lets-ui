## Keyboard

| Key | Action |
| --- | --- |
| `Esc` | Closes the Modal and returns focus to whatever opened it. With stacked dialogs, closes only the top one. |
| `Tab` / `Shift+Tab` | Moves through the elements of the window. Focus stays **trapped** inside it. |
| `Enter` or `Space` | Activates the focused button. |

## Screen reader

- The window is announced as a **modal dialog**, with the title as its name.
- The content behind the Modal is inaccessible while it is open.
- The close button has an accessible name (`close-label`, default "Close modal"). Translate it into the product's language.
- When closed, the Modal is out of the accessibility tree.

## Focus

On open, focus moves into the window. On close, it returns to the element that opened it.

This applies to every way of closing: `Esc`, the close button, the backdrop, an element with `data-modal-close`, `closeModal()` or removing `open`.

## Stacked dialogs

With one dialog open over another (a Drawer opened from inside the Modal, for example), `Esc` closes only the top one, and only it traps focus. Focus returns to the trigger inside the dialog that stays open, and a second `Esc` closes the one below.

A component inside the dialog that uses `Esc`, such as an open [Dropdown Menu](../../actionable/dropdown-menu/index.mdx) or a Toast, consumes the key: it closes that component, and the dialog stays open.

## Trigger

The Modal tells the trigger whether it is open (`aria-expanded`) and that it opens a dialog (`aria-haspopup`). On a [Button](../../actionable/button/index.mdx), [Icon Button](../../actionable/icon-button/index.mdx) or [Link](../../navigation/link/index.mdx), the state goes through the ARIA property and reaches the inner control, without creating an extra node in the accessibility tree. The trigger does not get `aria-controls`: the dialog's ID lives inside the shadow root, and the reference does not cross that boundary.

## For designers

- Every Modal needs a title.
- Make sure the task can be completed with the keyboard alone.
- Define the initial focus: in destructive confirmations, avoid placing it on the dangerous button.
