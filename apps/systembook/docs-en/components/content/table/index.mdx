## Best practices

<DosDonts variant="do" title="Comparable data">
  Each row is an item and each column, an attribute.
</DosDonts>

<DosDonts variant="do" title="Record listings">
  Users, orders, files or transactions.
</DosDonts>

<DosDonts variant="dont" title="Page layout">
  Tables are for data, not for positioning elements. Use [Grid](../../layout/grid/index.mdx) or [Flex](../../layout/flex/index.mdx).
</DosDonts>

<DosDonts variant="dont" title="Little data with no comparison">
  A simple list or a [Card](../card/index.mdx) communicates better.
</DosDonts>

<DosDonts variant="dont" title="Very heterogeneous content">
  When the rows have different structures, prefer cards.
</DosDonts>

## Anatomy

![Table anatomy: caption, header, row, cell and border](./anatomy.png)

1. **Caption** (optional): the visible title of the table.
2. **Header**: the name of each column.
3. **Rows**: one item per row.
4. **Cells**: the data. They can contain text, [Tags](../tag/index.mdx), [Avatars](../avatar/index.mdx), links and actions.
5. **Border and dividers**: organize the reading.

## Features

| Feature | What it does |
| --- | --- |
| **Border** (`bordered`) | Draws the outer border with rounded corners. |
| **End alignment** | Aligns value and action columns to the right. |
| **Fit column** | Shrinks a column to the width of its content (actions, status, ids). |
| **Sortable columns** | Buttons in the header, with an arrow indicating the order. |
| **Sticky header** | Keeps the header visible while the rows scroll. |
| **Horizontal scrolling** | When the table is wider than the space, it scrolls inside a region. |

## Cell content

Cells accept other components, and each one keeps its behavior: [Avatar](../avatar/index.mdx) with a name, [Link](../../navigation/link/index.mdx), status [Tag](../tag/index.mdx) and selection [Checkbox](../../form-and-options/checkbox/index.mdx).
