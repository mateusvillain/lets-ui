title: "Usage"
---

## Write short messages

- Say **what happened**, in up to six or seven words: "Changes saved".
- Use the tense that describes the result: "File deleted", not "Deleting file".
- Avoid final punctuation in the title and technical jargon.

<DosDonts variant="do" title="Objective confirmation">
  "Invite sent to ana@company.com". The person sees the result without stopping.
</DosDonts>

<DosDonts variant="dont" title="Long message that disappears">
  A paragraph explaining an error in a 5-second Toast. The person cannot read it in time.
</DosDonts>

## Action in the Toast

Offer an action only when it **helps undo or continue**: "Undo", "View file". When there is an action, the close button does not appear, and clicking the action also dismisses the Toast.

Use at most **one action**. If the person needs to decide something, use a Modal.

## Duration

- Simple messages: keep the default **5 seconds**.
- Messages with an action or more text: **give more time** (8 to 10 seconds) or use `duration="0"`.
- Errors: the `danger` Toast stays until it is closed.

## Quantity

Avoid showing several Toasts at the same time. They stack, but many messages compete with each other. Group similar messages ("3 files uploaded").

## Best practices

- Trigger the Toast **after** the action has completed, not before.
- Use the same place and the same style across the whole product.
- Do not use the Toast as the only notice of an important error.
- The content is treated as plain text: it does not work with HTML.
