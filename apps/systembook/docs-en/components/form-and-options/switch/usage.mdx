## Immediate effect

What defines the Switch is its **immediate effect**. When toggled, the system applies the change right away, with no further confirmation.

<DosDonts variant="do" title="Apply the change on toggle">
  Turning on "Email notifications" saves the preference at once. The person sees the result without extra steps.
</DosDonts>

<DosDonts variant="dont" title="Switch inside a form with Save">
  If the change only applies after clicking "Save", the person expects an immediate effect and gets confused. Use a Checkbox.
</DosDonts>

## Labels

- Describe **the feature**, not the action: "Email notifications", not "Turn on notifications".
- Use **nouns**, which work in both states.
- If the current state is not obvious, show helper text: "On" or "Off".
- Place the label next to the Switch, preferably on the right.

## Visual state

The state must be clear without relying on color: the thumb's position (left or right) communicates on and off. Avoid using red for "off": off is not an error.

## Best practices

- Use Switches in **settings lists**, with a label and a short description.
- Do not use a Switch to confirm a dangerous action.
- If the change takes a while to apply, show a progress indicator and handle failures, reverting the Switch with a message.
- Keep the size consistent within the same list.
