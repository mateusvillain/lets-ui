## Keyboard

| Key | Action |
| --- | --- |
| `Enter` or `Space` | Opens the menu from the trigger and activates the focused item. |
| `Down Arrow` | Moves to the next item (wraps to the first one at the end). |
| `Up Arrow` | Moves to the previous item (wraps to the last one at the start). |
| `Right Arrow` | Opens the submenu and focuses its first item. |
| `Left Arrow` | Closes the submenu and returns focus to the parent item. |
| `Esc` | Closes the menu and returns focus to the trigger. |
| `Tab` | Closes the menu and moves focus to after the trigger. |
| `Shift` + `Tab` | Closes the menu and moves focus to before the trigger. |

When it opens, focus goes to the first available item. Items stay **out of the `Tab` order** and are reached only with the arrows, so the whole menu is a single `Tab` stop, as in the Menu Button pattern of the ARIA Authoring Practices. Disabled items are skipped during navigation.

## Screen reader

- The trigger tells that it opens a menu (`aria-haspopup`) and whether it is open (`aria-expanded`).
- The panel is announced as `menu`, and each action as `menuitem`.
- Items with a submenu tell that they open another menu and their state.
- Dividers are announced as separators.

## For designers

- Give the trigger a clear name. If it is only an icon, it needs an accessible name ("More options").
- Do not rely on hover alone to open submenus: keyboard and touch must open them too.
- Dangerous items must be clear through their **text**, not just the red color.
