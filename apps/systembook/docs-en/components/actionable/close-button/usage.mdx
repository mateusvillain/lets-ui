## Position

Place the Close Button in the **top right corner** of the element it closes, where people expect to find it. In right-to-left languages, it goes to the top left corner.

<DosDonts variant="do" title="Always in the same place">
  Keep the button fixed in the corner, aligned with the title. A predictable position saves the person from searching for the way out.
</DosDonts>

<DosDonts variant="dont" title="Hidden or away from the corner">
  A small X in the middle of the content, or without contrast, makes the person feel trapped in the dialog.
</DosDonts>

## It is not the only way out

In dialogs, the Close Button sits alongside the action buttons ("Cancel", "Save"). It must close **without saving**, and the `Esc` key does the same.

<Callout variant="warning">
  If closing can discard unsaved work, warn first with a confirmation dialog. Do not silently lose what the person typed.
</Callout>

## Give the name context

The default accessible name is "Close". When using the button inside another component, describe what will be closed: "Close modal", "Close alert", "Remove Active filter". Set this with the `label` property, in the interface language.

## Best practices

- Use a size proportional to the container: `lg` in large headers and `sm` in alerts and tags.
- Do not use the Close Button for actions that do not close anything.
- In important alerts (errors), do not offer the option to close if the person needs to act first.
