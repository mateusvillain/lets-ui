The Let's UI components are native custom elements, so they work in any framework that renders HTML. In every case, the base is the same as in [Installation](./installation.mdx): load `@lets-ui/styles` and register the components once, in the entry point of the application.

```js
import '@lets-ui/styles';
import '@lets-ui/components';
```

Three things change from one framework to another:

- **Recognizing the `lui-*` tags**, so the framework does not complain about an unknown element.
- **Passing values**: text attributes work everywhere. Booleans and objects depend on the framework.
- **Listening to events**: the components dispatch their own events, like `menu-select` in the [Dropdown Menu](../../components/actionable/dropdown-menu/code.mdx). Each component's events are listed in its Code tab.

## React

### React 19

React 19 supports custom elements: it passes props as properties and binds custom events with `on` followed by the exact event name.

```jsx
export function Actions() {
  return (
    <lui-dropdown-menu onmenu-select={(event) => console.log(event.detail.label)}>
      <lui-button slot="trigger" variant="secondary">Options</lui-button>
      <lui-menu-item slot="items" label="Edit"></lui-menu-item>
      <lui-menu-item slot="items" label="Delete" variant="danger"></lui-menu-item>
    </lui-dropdown-menu>
  );
}
```

### React 18

React 18 passes everything as a text attribute and does not bind custom events. Listen to the events through a `ref`:

```jsx
import { useEffect, useRef } from 'react';

export function Actions() {
  const menu = useRef(null);

  useEffect(() => {
    const onSelect = (event) => console.log(event.detail.label);
    const element = menu.current;
    element.addEventListener('menu-select', onSelect);
    return () => element.removeEventListener('menu-select', onSelect);
  }, []);

  return <lui-dropdown-menu ref={menu}>{/* ... */}</lui-dropdown-menu>;
}
```

For booleans, pass `undefined` instead of `false`: React 18 writes the attribute `disabled="false"`, and an attribute that is present counts as true. Use `disabled={isDisabled || undefined}`.

### TypeScript

The package does not publish JSX types yet. For TypeScript to accept the `lui-*` tags, declare them once in your project:

```ts
// lets-ui.d.ts
import 'react';

declare module 'react' {
  namespace JSX {
    interface IntrinsicElements {
      [tag: `lui-${string}`]: any;
    }
  }
}
```

## Vue

Tell the Vue compiler that the `lui-*` tags are custom elements. With Vite:

```js
// vite.config.js
import vue from '@vitejs/plugin-vue';

export default {
  plugins: [
    vue({
      template: {
        compilerOptions: {
          isCustomElement: (tag) => tag.startsWith('lui-'),
        },
      },
    }),
  ],
};
```

Then use the tags and the events like any other element:

```vue
<lui-dropdown-menu @menu-select="(event) => console.log(event.detail.label)">
  <lui-button slot="trigger" variant="secondary">Options</lui-button>
  <lui-menu-item slot="items" label="Edit"></lui-menu-item>
</lui-dropdown-menu>
```

## Angular

Add `CUSTOM_ELEMENTS_SCHEMA` to the components that use the `lui-*` tags:

```ts
import { Component, CUSTOM_ELEMENTS_SCHEMA } from '@angular/core';

@Component({
  selector: 'app-actions',
  standalone: true,
  schemas: [CUSTOM_ELEMENTS_SCHEMA],
  template: `
    <lui-dropdown-menu (menu-select)="onSelect($event)">
      <lui-button slot="trigger" variant="secondary">Options</lui-button>
      <lui-menu-item slot="items" label="Edit"></lui-menu-item>
    </lui-dropdown-menu>
  `,
})
export class ActionsComponent {
  onSelect(event: Event) {
    console.log((event as CustomEvent).detail.label);
  }
}
```

Register the components in `main.ts` and import the CSS in the global `styles.css` (`@import '@lets-ui/styles';`) or in the `styles` list of `angular.json`.

## Svelte

Svelte recognizes custom elements without configuration and passes values as properties. Just register the components in the entry point and use the tags.

## Server rendering

The components register in the browser: on the server, `customElements` does not exist. In Next.js, Nuxt, SvelteKit or Astro, import `@lets-ui/components` on the client only. The HTML with the `lui-*` tags can come from the server: the browser upgrades each component when the registration loads.

```jsx
// Next.js (App Router)
'use client';

import { useEffect } from 'react';

export function LetsUI() {
  useEffect(() => {
    import('@lets-ui/components');
  }, []);
  return null;
}
```

```ts
// Nuxt: plugins/lets-ui.client.ts
import '@lets-ui/components';

export default defineNuxtPlugin(() => {});
```

The CSS (`@lets-ui/styles`) can be loaded normally on the server, in the root layout.

## Forms

Input, Textarea, Select, Checkbox, Radio, Radio Group, Switch, OTP Input, Date Picker and Button take part in native forms. Inside a `<form>`, their values go into the submission and into `FormData` under their `name`, and form validation (`required`, `form.checkValidity()`, blocking the submission) takes them into account. You can use these fields with native submission or read their values from each component's events in your form library.
