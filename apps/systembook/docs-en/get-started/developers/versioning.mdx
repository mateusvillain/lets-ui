## One version for the three packages

`@lets-ui/tokens`, `@lets-ui/styles` and `@lets-ui/components` are published **always together and with the same number**. When one changes, all three get a new version. So the right combination is always the one with matching numbers: `@lets-ui/styles@1.13.1` with `@lets-ui/components@1.13.1`.

```json
{
  "dependencies": {
    "@lets-ui/styles": "^1.13.1",
    "@lets-ui/components": "^1.13.1"
  }
}
```

## Semantic versioning

The number follows [Semantic Versioning](https://semver.org/): `major.minor.patch`.

| Version | When it goes up | Examples |
| --- | --- | --- |
| **Patch** (`1.13.0` → `1.13.1`) | Fixes that do not change the API. | A focus bug, a contrast adjustment, a corrected accessible text. |
| **Minor** (`1.12` → `1.13`) | New features compatible with what already exists. | A new component, a new attribute, a new variant. |
| **Major** (`1.x` → `2.0`) | Changes that can break your code. | Removing or renaming a documented attribute, event, CSS class or custom property. |

With `^` in `package.json`, you get fixes and new features automatically, and a major version only comes in when you upgrade on purpose. Through the CDN, the `@1` in the URL has the same effect. See [Installation](./installation.mdx).

## Where to see what changed

- The [CHANGELOG](https://github.com/mateusvillain/lets-ui/blob/main/CHANGELOG.md) lists every version, split into **Added**, **Changed**, **Fixed** and **Removed**.
- The [releases on GitHub](https://github.com/mateusvillain/lets-ui/releases) carry the same notes, with the tag of each version.
- In this documentation, a component whose behavior changed has its page updated in the same version.

Before upgrading to a major version, read its **Changed** and **Removed** sections: that is where the changes that need adjustments in your code are.
