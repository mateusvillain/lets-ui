**Let's UI** brings a product's design and code decisions together in one place: colors, typography, spacing, components and the rules for when and how to use them. The goal is for designers, developers and content writers to work with the **same language**, and for a decision made once to hold across the whole product.

## What it is for

- **Consistency**: the same button, the same spacing and the same tone on every screen.
- **Speed**: ready, documented components, instead of starting over on every screen.
- **Accessibility from the start**: every component is designed for the keyboard, for screen readers and for contrast, aiming at WCAG 2.2 level AA.
- **Brand and theme**: the same system serves **light and dark mode** and **multiple brands**, just by swapping tokens.
- **Technology independence**: it works in React, Vue, Angular, Svelte or plain HTML.

## What you will find here

| Part | What you find |
| --- | --- |
| **Foundations** | Color, typography, spacing, borders, elevation, accessibility and writing: the base of everything. |
| **Components** | Every component, with when to use it, best practices, accessibility and code. |
| **Utilities** | Functions, mixins and classes that help you build with the tokens. |

## How to read a component page

Every component page follows the same structure, in four tabs:

| Tab | What for |
| --- | --- |
| **Overview** | What it is, when to use it and when not to, anatomy, variants, sizes and states. |
| **Usage** | How to use it well: do and don't, writing, placement, behavior and best practices. |
| **Accessibility** | Keyboard, screen reader, contrast and what the design has to guarantee. |
| **Code** | Properties, events and code examples. |
