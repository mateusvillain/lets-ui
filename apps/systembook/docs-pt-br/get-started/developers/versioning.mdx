## Uma versão para os três pacotes

`@lets-ui/tokens`, `@lets-ui/styles` e `@lets-ui/components` são publicados **sempre juntos e com o mesmo número**. Quando um muda, os três sobem de versão. Assim, a combinação certa é sempre a de números iguais: `@lets-ui/styles@1.13.1` com `@lets-ui/components@1.13.1`.

```json
{
  "dependencies": {
    "@lets-ui/styles": "^1.13.1",
    "@lets-ui/components": "^1.13.1"
  }
}
```

## Versionamento semântico

O número segue o [Semantic Versioning](https://semver.org/lang/pt-BR/): `maior.menor.correção`.

| Versão | Quando sobe | Exemplos |
| --- | --- | --- |
| **Correção** (`1.13.0` → `1.13.1`) | Correções que não mudam a API. | Um bug de foco, um ajuste de contraste, um texto acessível corrigido. |
| **Menor** (`1.12` → `1.13`) | Novidades compatíveis com o que já existe. | Um componente novo, um atributo novo, uma variante nova. |
| **Maior** (`1.x` → `2.0`) | Mudanças que podem quebrar o seu código. | Remover ou renomear um atributo, um evento, uma classe CSS ou uma custom property documentada. |

Com o `^` no `package.json`, você recebe correções e novidades automaticamente, e uma versão maior só entra quando você atualiza de propósito. Pela CDN, o `@1` na URL tem o mesmo efeito. Veja a [Installation](./installation.mdx).

## Onde ver o que mudou

- O [CHANGELOG](https://github.com/mateusvillain/lets-ui/blob/main/CHANGELOG.md) lista cada versão, dividida em **Added**, **Changed**, **Fixed** e **Removed**.
- As [releases no GitHub](https://github.com/mateusvillain/lets-ui/releases) trazem as mesmas notas, com a tag de cada versão.
- Nesta documentação, um componente que mudou de comportamento tem a página atualizada na mesma versão.

Antes de atualizar para uma versão maior, leia as seções **Changed** e **Removed** dela: é onde ficam as mudanças que pedem ajuste no seu código.
