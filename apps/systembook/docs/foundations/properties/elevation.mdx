## Purpose

Elevation **communicates layer, it does not decorate**. It answers a question for the person: "is this part of the page, or is it temporarily on top of it?". A floating menu, a modal that blocks the screen and a card at rest need to look like different things, because they behave in different ways.

## Principles

- **Height is priority and transience.** The higher it is, the more attention it asks for and the more temporary it is: a menu closes, a modal is dismissed.
- **Shadow alone is rarely enough.** Each level combines shadow, surface color and, when needed, a border.
- **Few levels per screen.** Shadow on everything is the same as shadow on nothing.
- **Going up a level has a reason.** An element only rises because it is floating, blocking the page or reacting to interaction.
- **The order is fixed.** A higher level always sits on top of a lower one.

## The levels

| Level | Meaning | Surface | Border | Examples |
| --- | --- | --- | --- | --- |
| **Flat** (no shadow) | Part of the page. | `neutral.background.surface` or `container` | Optional, `border.subtle` | Sections, tables, fields. |
| `base` | A surface at rest, set apart from the page. | `neutral.background.surface` | `border.subtle` in the dark theme | [Card](../../components/content/card/index.mdx) with elevation. |
| `hovered` | A surface at rest that reacted to the pointer. | Same as at rest | Same as at rest | Interactive card on hover. |
| `floating` | Floats over the page, tied to a trigger. Does not block the rest. | `neutral.background.surface` or `overlay` | `border.subtle` | [Dropdown Menu](../../components/actionable/dropdown-menu/index.mdx), [Tooltip](../../components/content/tooltip/index.mdx), [Toast](../../components/content/toast/index.mdx). |
| `overlay` | The highest layer: blocks the page until dismissed. | `neutral.background.surface` | None | [Modal](../../components/content/modal/index.mdx), [Drawer](../../components/content/drawer/index.mdx). |

## Tokens

Each level is a **two-layer** shadow: a diffuse one, with no offset, that outlines the surface, and one offset downward, that gives the sense of height. The higher the level, the larger the offset, blur and opacity.

| Level | Outline layer | Height layer |
| --- | --- | --- |
| `base` | `0 0 8px`, 2% | `0 4px 12px`, 4% |
| `hovered` | `0 0 8px`, 4% | `0 8px 16px`, 8% |
| `floating` | `0 0 8px`, 8% | `0 12px 20px`, 12% |
| `overlay` | `0 1px 8px`, 4% | `0 16px 24px`, 16% |

<TokenTable group="lui.elevation" />

Apply it with the SCSS function `elevation($level)`, with the utility class `.elevation-{level}` or with the custom property `var(--lui-elevation-{level})`.

```scss
.floating-panel {
  background-color: bg(surface, neutral);
  border: width(1) solid stroke(neutral, subtle);
  border-radius: radius(lg);
  box-shadow: elevation(floating);
}
```

## Stacking

The stacking order follows the levels. The `z-index` values **are not tokens**: they are the same in every brand and theme, so they live in the components. This is the ladder they follow:

| Layer | `z-index` | Components |
| --- | --- | --- |
| Page content | `auto` to `1` | Tooltip (anchored to the trigger), Table sticky header, Float |
| Menus | `100` | Dropdown Menu |
| Backdrop | `1040` | Dimmed background of the Drawer and the Modal |
| Overlays | `1050` | Modal, Drawer |
| Notifications | `1060` | Toast |

In practice: **content < menus < backdrop < modal and drawer < toast**. A toast appears on top of an open modal, because the notification may be about the action that just happened inside it.

<Callout variant="tip">
  A new element that needs to float goes **on one of the rungs of the ladder**, never between them. If no rung fits, the problem is probably about the layer, not the number.
</Callout>

## Dark theme

Shadows are black and **the same in both themes**. On a dark surface, a black shadow barely shows, so in the dark theme the separation between layers comes from **surface and border**:

- Use `neutral.border.subtle` on `base` and `floating` surfaces that need to stand out from the background, such as the Card with the border option.
- The Tooltip already uses `neutral.background.overlay`, which is light in the dark theme and dark in the light one: it stands out in both without relying on the shadow.
- `overlay`-level overlays use a **backdrop**, which separates the layer even when the shadow disappears.

<Callout variant="info">
  The system does not yet have dedicated elevated surfaces for the dark theme (a lighter tone per level). Until then, the subtle border is the recommended reinforcement.
</Callout>

## Interaction

- `hovered` is the only **state** level: an interactive card goes from `base` to `hovered` on hover, with a transition.
- An element does not change level when clicked or focused. Focus has its own indicator, the focus ring. See [Border](border.mdx).
- Surfaces that enter the screen (menu, modal, toast) appear already at their level. The entrance animation is of opacity and position, not shadow.

## Accessibility

- **Elevation cannot be the only cue.** Many people do not perceive subtle shadows, and they disappear in high contrast mode. Combine it with a border, a background change or a backdrop.
- **Blocking layers trap focus.** An `overlay` element moves focus inside, keeps focus trapped while it is open, closes with `Esc` and returns focus to the trigger.
- **Nothing important underneath something fixed.** A fixed header or a toast cannot hide the element that has focus (WCAG 2.4.11).
- **Toasts** sit on top of everything, but do not steal focus.

## Best practices

- Use **one** floating level and **one** overlay level at a time. An open menu inside a modal is the limit.
- Prefer **border** to **shadow** to separate areas within the same layer.
- Combine `overlay` with a backdrop whenever the layer blocks the page.
- In the dark theme, check that each elevated surface is still distinguishable from the background.

## Anti-patterns

<DosDonts variant="do" title="Elevation with meaning">
  The open menu at `floating`, the modal at `overlay`, the rest flat. The person senses which layer they are on.
</DosDonts>

<DosDonts variant="dont" title="Shadows on everything">
  Cards, buttons, fields and tags, all with shadows. The screen gets heavy, and the hierarchy disappears.
</DosDonts>

- **Shadow as decoration.** A shadow on a button to "add depth" suggests it floats.
- **In-between levels.** A shadow "between `base` and `floating`" is a level nobody else understands.
- **`z-index: 9999`.** A numbers race the next component will lose. Use the ladder.
- **Relying on the shadow in the dark theme.** Without a border or a surface change, the layer disappears.
