## Keyboard

| Key | Action |
| --- | --- |
| `Tab` | Moves through the controls inside the cells (links, buttons, checkboxes) in reading order. |
| `Enter` or `Space` | Activates the sort button or the focused control. |
| `Arrows` | When the table scrolls, the region receives focus and the arrows scroll the content. |

## Screen reader

- Table uses the native `<table>`, so the screen reader announces rows, columns and headers as in any table.
- Use `<th scope="col">` on column headers and `<th scope="row">` on the cell that identifies the row.
- Every table needs a **name**: the caption (`<caption>`), when the title is visible, or `aria-label`, when it is not.
- Sortable columns convey the current order (`aria-sort`) and carry the column name.
- Controls inside cells need names that mention the row ("Select Customer base.csv").

## Scrolling

When the table is larger than the space, the scrollable region is announced with a name and can receive focus, so keyboard users can also scroll.

## Visual

- The sort arrows have a contrast above 3:1.
- The row highlight on hover is only an aid: no information depends on it.
- Status never depends on color alone: use text in the tag.

## For designers

- Define the table title and the header of each column during design.
- Decide which cell identifies each row (usually the name).
- Avoid empty cells without explanation. Use a dash ("—") or "No data".
