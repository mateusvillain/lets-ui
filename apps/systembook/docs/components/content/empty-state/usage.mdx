## Write the content

- **Title**: says what is happening, in a few words. "No projects yet."
- **Description**: explains the reason and guides. "Create your first project to get started."
- **Action**: a clear verb. "Create project".

<DosDonts variant="do" title="Explains and invites">
  "No results for 'blue shirt'. Try another term or remove the filters."
</DosDonts>

<DosDonts variant="dont" title="Only states the emptiness">
  "No data." It neither explains the reason nor says what to do.
</DosDonts>

## A single primary action

Offer **only one main action**. If there is nothing the person can do (for example, waiting for an external process), **do not invent a button**.

## Cover

- Use a cover in large spaces and on first use.
- **Omit** it in small spaces and when several Empty States appear together, such as several widgets with no data. Repeating the same illustration reduces the impact.
- The cover is decorative: everything that matters needs to be in the text.

## Tone

Match the tone to the situation. Be positive on first use, neutral when something was not found, and serious in errors. Avoid humor in errors and data loss.

## Dynamic behavior

- When the Empty State appears **as the result of an action** (search, filter, deletion), announce it to screen readers.
- In searches, wait for the person to finish typing before switching to the Empty State, so it does not flicker with each keystroke.
- If focus was on the deleted item, move it to a predictable place, such as the search field.

## Best practices

- Use a heading hierarchy consistent with the page (`title-level`).
- Translate long texts without worry: the block grows in height without truncating.
- On small screens, the buttons take the full width.
