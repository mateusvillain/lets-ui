## Keyboard

| Key | Action |
| --- | --- |
| `Tab` / `Shift+Tab` | Enters and leaves the field. |
| `Up/Down Arrow` | In number fields, increases and decreases the value. |
| `Enter` | Submits the form, when there is one. |

## Screen reader

- The label is associated with the field, and the reader announces the name on entering it.
- The hint and the error message are read along with the field (`aria-describedby`).
- On error, the field is announced as invalid (`aria-invalid`). Required fields are announced as required.
- The show password and increase and decrease buttons have their own names. Change the default texts (in English) to the product's language.

## Visual

- The typed text and the label have a minimum contrast of 4.5:1, and the field border, 3:1.
- The error state uses text and an icon in addition to color.
- Focus is visible with a ring around the field.

## For designers

- Never use the placeholder alone as the label.
- Write error messages that explain how to fix the problem.
- Use the right `type` and `inputmode` attributes: they improve the experience for people using a virtual keyboard or assistive technology.
- Let password managers and autofill work.
