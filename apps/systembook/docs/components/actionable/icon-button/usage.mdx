## Choose recognizable icons

Use the metaphors people already know: a trash can to delete, a pencil to edit, a magnifying glass to search, three dots for more options.

<DosDonts variant="do" title="One icon, one meaning">
  Use the same icon for the same action across the whole product. Someone who learned the pencil for "Edit" does not need to relearn it on the next screen.
</DosDonts>

<DosDonts variant="dont" title="Ambiguous or made-up icons">
  An icon with no convention forces the person to click to find out what it does. When in doubt, use text.
</DosDonts>

## Always give it a name

With no visible text, the action's name only exists for screen readers, and it comes from `aria-label`. It is **required**.

- Describe the **action**, not the image: "Delete", not "Trash can".
- In lists, include the target: "Delete file relatorio.pdf".

## Help with a tooltip

For less obvious actions, pair the Icon Button with a [Tooltip](../../content/tooltip/index.mdx). The tooltip reveals the name on hover and on keyboard focus, and helps people who are learning the interface.

## Spacing and grouping

- Keep at least 8px between neighboring Icon Buttons to avoid mistaken taps.
- Group related actions and separate different groups with a [Divider](../../layout/divider/index.mdx).
- If there are more than three or four actions, group the less used ones in a [Dropdown Menu](../dropdown-menu/index.mdx).

## Best practices

- Use icons of the same style, stroke weight and size across the whole interface.
- Do not mix Icon Buttons and text Buttons in the same row of actions without need.
- Avoid icon-only destructive actions: ask for confirmation or offer "Undo".
