## Keyboard

| Key | Action |
| --- | --- |
| `Tab` | Moves focus to the button. |
| `Enter` or `Space` | Activates the action. |

## Screen reader

- `aria-label` is **required**: with no visible text, it is the button's only name. A missing or empty `aria-label` is a failure.
- The SVG icon is decorative and stays out of the accessibility tree, so it is not read twice.
- A disabled button is announced as unavailable and leaves the tab order.
- On a toggle button, `aria-pressed` announces "pressed" or "not pressed". Keep the same `aria-label` in both states: a name that changes with the state is confusing.
- When the button opens something, `aria-expanded` and `aria-haspopup` convey the state. As the trigger of a Modal, Drawer or Dropdown Menu, the button gets this state from the component itself.
- `aria-label`, `aria-expanded`, `aria-haspopup` and `aria-pressed` move to the inner `<button>` and leave `<lui-icon-button>`, so no extra node is created in the accessibility tree.

## Visual

- Icon and background need a contrast of at least 3:1 (WCAG 2.2 AA for interface components).
- The focus ring appears when navigating by keyboard.
- The 32px (`md`) and 40px (`lg`) touch targets are larger than the 24px minimum of WCAG 2.2.
- In high contrast mode (`forced-colors`), the pressed button uses the system highlight colors and gets an inner ring, and the disabled one uses `GrayText`.

## For designers

- Never hand off an Icon Button without defining the `aria-label` text. Make it part of the component specification.
- Do not rely on the icon alone: a tooltip helps people who have trouble recognizing symbols.
- On a toggle button, show the state through shape too, not just the background color, when the state matters to the task.
