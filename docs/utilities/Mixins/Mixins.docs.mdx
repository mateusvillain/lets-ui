## Breakpoints de referência

Os mixins `media-up()` e `media-down()` usam internamente a função `breakpoint()`,
que lê os tokens de marca `lui.brand.grid.breakpoint.*`. Os valores abaixo são os
da marca `lets-ui` — uma marca que redefinir esses tokens muda a tabela inteira.

| Nome  | Largura | Significado                                      |
| ----- | ------- | ------------------------------------------------ |
| `1xs` | 767px   | Teto da faixa mobile — só existe em `media-down` |
| `sm`  | 768px   | Piso a partir do qual o step abre                |
| `md`  | 1024px  | Piso a partir do qual o step abre                |
| `lg`  | 1280px  | Piso a partir do qual o step abre                |
| `1xl` | 1440px  | Piso a partir do qual o step abre                |

`1xs` é o step base e corre no sentido oposto aos demais: é a largura máxima que
o layout mobile sustenta, não um mínimo. Por isso `media-up(1xs)` é um erro de
compilação — abaixo dele só existem os estilos base, que não precisam de media
query.

`media-down()` para estritamente abaixo do piso do step, e não um pixel abaixo
dele: `media-down(lg)` gera `width < 1280px`, complemento exato de
`min-width: 1280px` que `media-up(lg)` gera. Um teto inclusivo (`<= 1279px`)
deixaria uma fresta — em uma largura fracionária como 1279.5px, que zoom de
browser e escala de display produzem, nenhuma das duas consultas casaria e o
elemento ficaria sem regra. Como `1xs` não é um piso, seu limite é o piso do
step acima: `media-down(1xs)` gera `width < 768px`.

> A largura de `1xs` na tabela é o teto conceitual da faixa mobile e serve de
> referência; nenhuma media query lê esse valor, justamente porque o limite
> exato é o piso de `sm`.

</Lang>

## Reference breakpoints

The `media-up()` and `media-down()` mixins internally use the `breakpoint()`
function, which reads the `lui.brand.grid.breakpoint.*` brand tokens. The values
below are from the `lets-ui` brand — a brand that redefines those tokens changes
the whole table.

| Name  | Width  | Meaning                                            |
| ----- | ------ | -------------------------------------------------- |
| `1xs` | 767px  | Mobile range ceiling — only exists in `media-down` |
| `sm`  | 768px  | Floor from which the step opens                    |
| `md`  | 1024px | Floor from which the step opens                    |
| `lg`  | 1280px | Floor from which the step opens                    |
| `1xl` | 1440px | Floor from which the step opens                    |

`1xs` is the base step and runs in the opposite direction from the others: it is
the maximum width the mobile layout supports, not a minimum. That is why
`media-up(1xs)` is a compilation error — below it there are only the base styles,
which do not need a media query.

`media-down()` targets strictly below the step floor, not one pixel below it:
`media-down(lg)` generates `width < 1280px`, the exact complement of the
`min-width: 1280px` that `media-up(lg)` generates. An inclusive ceiling
(`<= 1279px`) would leave a gap — at a fractional width such as 1279.5px, which
browser zoom and display scaling produce, neither query would match and the
element would be left without a rule. Since `1xs` is not a floor, its limit is
the floor of the step above: `media-down(1xs)` generates `width < 768px`.

> The `1xs` width in the table is the conceptual ceiling of the mobile range and
> serves as a reference; no media query reads that value, precisely because the
> exact limit is the `sm` floor.

</Lang>
